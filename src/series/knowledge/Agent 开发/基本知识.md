# Agent 开发基础知识

## 什么是 LLM？

LLM（Large Language Model）大语言模型，是基于海量文本数据训练的深度学习模型。

核心特点：
1. **理解能力** - 理解自然语言指令
2. **生成能力** - 生成流畅的文本回复
3. **推理能力** - 进行逻辑推理和问题解决
4. **泛化能力** - 适应不同任务和领域

## 什么是 Prompt Engineering？

Prompt Engineering（提示工程）是设计和优化输入提示，以引导 LLM 产生期望输出的技术。

核心原则：
1. **明确具体** - 清晰描述任务要求
2. **提供上下文** - 给出必要的背景信息
3. **示例引导** - 使用 Few-Shot 示例
4. **结构化输出** - 指定期望格式

常用技巧：
- Zero-Shot：直接提问
- Few-Shot：提供示例
- Chain of Thought：引导逐步推理
- Role Playing：设定角色

## 什么是 Token？

Token 是 LLM 处理文本的基本单位。

要点：
1. **计算单位** - 模型按 Token 计费
2. **长度限制** - 上下文窗口限制（如 128K）
3. **中英文差异** - 英文约 1 Token=0.75 词，中文约 1 Token=1.5 字
4. **影响成本** - Token 数直接影响 API 费用

## 什么是 Temperature 参数？

Temperature 控制 LLM 输出的随机性。

取值范围：0 ~ 2

| 值 | 效果 | 适用场景 |
|----|------|----------|
| 0~0.3 | 确定性强，答案稳定 | 事实问答、代码生成 |
| 0.5~0.7 | 平衡 | 通用对话 |
| 1.0+ | 创意性强，变化多 | 创意写作、头脑风暴 |

## 什么是 System Prompt？

System Prompt 是系统级别的指令，用于设定 AI 的行为准则和角色。

示例：
```
你是一个专业的编程助手，擅长 Python 和 Java 开发。
请用简洁的语言回答问题，并提供代码示例。
```

特点：
1. **优先级高** - 比用户指令优先级更高
2. **全局生效** - 影响整个对话
3. **隐藏设置** - 用户通常看不到

## 什么是 Context Window？

Context Window（上下文窗口）是模型一次能处理的最大 Token 数。

要点：
1. **包含输入和输出** - Prompt + 回复总计
2. **越长越贵** - 长上下文成本更高
3. **注意力稀释** - 过长可能影响关键信息关注


## 什么是 Embedding？

Embedding（嵌入）是将文本转换为向量表示的技术。

特点：
1. **语义相似** - 语义相近的文本向量距离近
2. **数值表示** - 通常是几百维的浮点数向量
3. **RAG 基础** - 是检索增强生成的核心技术

常见模型：
- text-embedding-3-small/large（OpenAI）
- bge 系列（智源）
- m3e 系列（国产）

## 什么是向量数据库？

向量数据库是专门存储和检索向量数据的数据库。

核心功能：
1. **向量存储** - 存储 Embedding 向量
2. **相似度搜索** - 快速找到最相似的向量
3. **元数据管理** - 关联原始文本和元信息

常见产品：
- FAISS（Facebook，轻量级）
- Chroma（开源，易用）
- PGVector（PostgreSQL 扩展）
- Milvus（分布式）
- Pinecone（云服务）

## 什么是 RAG？

RAG（Retrieval-Augmented Generation）检索增强生成，是通过检索外部知识库来增强 LLM 回答质量的技术。

核心流程：
```
1. 文档加载 → 2. 文本分块 → 3. 向量化
              ↓
4. 存储到向量数据库
              ↓
5. 用户提问 → 6. 语义检索 → 7. 增强生成
```

优势：
1. **知识更新** - 无需重新训练即可更新知识
2. **减少幻觉** - 基于真实文档回答
3. **可追溯** - 可追溯回答来源

## 什么是 Function Calling？

Function Calling（函数调用）让 LLM 能够调用外部函数获取实时信息或执行操作。

工作流程：
1. 定义函数描述（名称、参数、功能）
2. LLM 根据上下文决定是否调用及参数
3. 执行函数并返回结果给 LLM
4. LLM 生成最终响应

应用场景：
- 获取实时数据（天气、股价）
- 执行数据库查询
- 调用外部 API
- 操作内部系统

## 什么是 Agent？

Agent（智能体）是能够感知环境、做出决策并执行行动的智能系统。

核心能力：
1. **感知** - 接收输入信息
2. **规划** - 分解任务、制定计划
3. **行动** - 调用工具执行
4. **记忆** - 维护上下文和历史

典型架构：
```
用户输入 → 规划 → 选择工具 → 执行 → 观察结果 → 生成回答
```

## 什么是 Chain？

Chain（链）是将多个 LLM 调用或组件按顺序组合的模式。

特点：
1. **线性执行** - 按预定顺序执行
2. **传递状态** - 上一步输出作为下一步输入
3. **可组合** - 多个 Chain 可以嵌套

示例场景：
- 多步骤文本处理
- 固定流程的任务

## 什么是 Multi-Agent System？

Multi-Agent System（多智能体系统）是多个 Agent 协作完成复杂任务的系统。

协作模式：
1. **分工协作** - 不同 Agent 负责不同任务
2. **审核机制** - 一个生成，一个审核
3. **投票决策** - 多个 Agent 投票决定

典型架构：
- Manager-Worker：管理者分配任务
- Peer-to-Peer：平等协作
- Hierarchical：层级管理

## 什么是 Human-in-the-loop？

Human-in-the-loop（人在回路）是在 AI 决策流程中引入人工审核的机制。

应用场景：
1. **内容审核** - 敏感内容需要人工确认
2. **重要决策** - 关键操作需要审批
3. **质量检查** - 输出质量需要验证
4. **边界情况** - AI 不确定时转人工

实现方式：
- 流程暂停等待审批
- 提供修改建议
- 确认后再执行

## AI 幻觉是什么？如何缓解？

AI 幻觉（Hallucination）是 LLM 生成看似合理但不准确或虚构的内容。

缓解方法：
1. **RAG** - 基于检索的真实文档
2. **引用溯源** - 要求提供来源
3. **工具调用** - 实时获取准确数据
4. **约束输出** - 限制在给定范围内
5. **验证机制** - 多重确认关键信息

## Agent 和 Chain 的区别是什么？

Agent 是自主决策的系统，根据任务动态选择工具；Chain 是预定义的固定流程，按顺序执行步骤。

1. **决策方式** - Agent 根据上下文动态决策，Chain 按预定顺序执行
2. **灵活性** - Agent 可以适应不同任务，Chain 适用于固定流程
3. **复杂度** - Agent 有规划、记忆、反思能力，Chain 只是组件串联
4. **适用场景** - Agent 适合复杂不确定任务，Chain 适合多步骤固定流程

## Function Calling 如何定义和使用？

Function Calling 需要定义函数的名称、描述、参数结构，LLM 会根据任务判断是否调用。

1. **定义 Schema** - 使用 JSON Schema 描述函数名、描述、参数
2. **注册工具** - 将函数描述传给 LLM
3. **解析响应** - LLM 返回函数调用指令或直接回答
4. **执行函数** - 在本地调用函数并返回结果
5. **继续对话** - 将函数结果返回给 LLM 生成最终回答

## Agent 的记忆机制有哪些类型？

记忆机制包括短期记忆、长期记忆和工作记忆，分别管理对话历史、知识库和任务状态。

1. **短期记忆** - 对话历史，维护当前会话上下文
2. **长期记忆** - 知识库存储，跨会话持久化信息
3. **工作记忆** - 任务执行过程中的临时状态
4. **向量记忆** - 基于向量数据库的语义记忆检索

## 如何处理 Agent 执行失败？

需要设计重试机制、错误处理流程和降级策略，确保系统的健壮性。

1. **重试机制** - 对临时性错误设置指数退避重试
2. **错误分类** - 区分可恢复错误和不可恢复错误
3. **降级策略** - 工具不可用时切换备用方案
4. **人工介入** - 关键错误触发 Human-in-the-loop
5. **日志记录** - 详细记录失败上下文用于调试

## Multi-Agent System 中 Agent 之间如何协作？

通过消息传递、共享状态或中央调度器实现 Agent 间的信息交换和任务协调。

1. **消息传递** - Agent 间直接发送消息
2. **共享状态** - 通过共享内存或数据库交换信息
3. **中央调度** - Manager Agent 分配和协调任务
4. **角色分工** - 不同 Agent 承担不同角色（生成、审核、修正）
5. **迭代优化** - Agent A 生成，Agent B 提供反馈迭代改进

## RAG 的检索策略有哪些？

包括向量检索、关键词检索、混合检索和递归检索，根据场景选择合适策略。

1. **向量检索** - 基于语义相似度检索最相关文档
2. **关键词检索** - BM25 等传统全文检索
3. **混合检索** - 结合向量和关键词，提升准确率
4. **递归检索** - 检索后分解子问题继续检索
5. **元数据过滤** - 先按元数据筛选再向量检索

## Prompt Engineering 中 Zero-Shot、Few-Shot 和 CoT 的区别？

Zero-Shot 直接提问，Few-Shot 提供示例引导，CoT 引导模型逐步推理思考过程。

1. **Zero-Shot** - 不提供示例，直接描述任务要求
2. **Few-Shot** - 提供 2-5 个示例，让模型模仿模式
3. **CoT** - Chain of Thought，要求模型展示思考步骤，提升复杂任务效果
4. **选择依据** - 简单任务用 Zero-Shot，需要模式匹配用 Few-Shot，复杂推理用 CoT

## 如何优化 Token 使用效率？

通过精简 Prompt、压缩上下文、分层存储等方式减少 Token 消耗，降低成本。

1. **精简 Prompt** - 去除冗余描述，保留核心指令
2. **上下文压缩** - 对历史对话进行摘要压缩
3. **分层存储** - 长期知识用向量库检索，短期对话保留原始
4. **批处理** - 多个任务合并为一次 API 调用
5. **选择模型** - 根据任务选择合适大小的模型

## Human-in-the-loop 适合哪些场景？

适用于需要安全审核、重要决策、质量保证或边界情况处理的场景。

1. **内容安全** - 生成内容需要人工审核敏感信息
2. **重要决策** - 涉及资金、权限等关键操作需审批
3. **质量保证** - 要求高准确率的输出需要验证
4. **边界情况** - AI 置信度低时转人工处理
5. **学习反馈** - 收集人工反馈优化系统

## Agent 工具调用的参数如何验证？

使用 JSON Schema 定义参数类型和约束，LLM 解析后进行验证，确保工具调用安全。

1. **Schema 定义** - 使用 JSON Schema 定义参数类型、范围、必填项
2. **类型检查** - 验证参数是否符合预期类型
3. **范围校验** - 检查数值范围、枚举值等约束
4. **默认值** - 为可选参数提供合理默认值
5. **错误提示** - 验证失败时返回清晰错误信息

## 如何评估 Agent 的性能？

通过准确性、效率、可靠性和用户体验等维度建立综合评估体系。

1. **准确性** - 任务完成率和答案质量
2. **效率** - 响应时间和 Token 消耗
3. **可靠性** - 错误率和重试次数
4. **成本** - API 调用费用和资源消耗
5. **用户体验** - 对话流畅度和满意度

## Agent 开发中常见的陷阱有哪些？

包括过度复杂化、缺乏错误处理、内存泄露和安全漏洞等常见问题。

1. **过度设计** - 简单任务用复杂架构
2. **错误处理缺失** - 未处理工具调用失败
3. **内存管理** - 长对话未压缩导致超限
4. **安全漏洞** - 工具调用未做权限验证
5. **过度依赖模型** - 未使用 RAG 或工具增强能力
