# Dify 面试题

## Dify 是什么？

开源的 LLM 应用开发平台，提供可视化工作流编排、RAG 管道、Agent 等能力。支持多模型，可视化拖拽开发，降低 AI 应用门槛。

## Dify 支持哪些应用类型？

1. **聊天助手** - 对话式 AI 应用
2. **工作流** - 可视化编排复杂流程
3. **Agent** - 自主决策的智能体
4. **文本生成** - 结构化内容生成

## Dify 的工作流由哪些节点组成？

1. **开始节点** - 定义输入参数
2. **LLM 节点** - 调用大模型
3. **工具节点** - 执行外部 API
4. **条件节点** - 分支判断
5. **结束节点** - 定义输出格式

## Dify 的 Agent 能力有哪些？

1. **工具调用** - 自动选择并调用工具
2. **多轮对话** - 维护对话上下文
3. **任务规划** - 分解复杂任务
4. **自动执行** - 自主完成多步操作

## Dify 支持哪些内置工具？

1. **搜索引擎** - Google、Bing 搜索
2. **计算器** - 数学计算
3. **代码执行** - Python 沙箱
4. **日期时间** - 获取当前时间
5. **HTTP 请求** - 调用外部 API

## Dify 的 RAG 引擎如何工作？

1. **文档上传** - 支持 PDF、Word、TXT、Markdown 等
2. **自动解析** - 提取文本内容
3. **智能分块** - 自动切分成片段
4. **向量化** - 调用 Embedding 模型存入向量数据库
5. **混合检索** - 语义检索 + 关键词检索
6. **引用溯源** - 返回答案附带来源

## Dify 的知识库如何管理？

1. **多格式支持** - PDF、Word、Markdown 等
2. **批量上传** - 支持文件夹上传
3. **分段管理** - 手动调整分块大小
4. **命中测试** - 测试检索效果，调整阈值

## Dify 支持哪些检索模式？

1. **语义检索** - 向量相似度匹配
2. **关键词检索** - BM25 算法
3. **混合检索** - 两者结合，加权排序

## 为什么推荐混合检索？

1. **单一检索的局限**

   - 纯语义：专有名词、编号查不准
   - 纯关键词：同义词、语义理解差
2. **混合检索优势**

   - 语义检索理解意图
   - 关键词检索匹配精确词汇
   - 两者结合效果更好

## RAG 的工作流程是什么？

1. **文档处理**：上传 → 提取文本 → 分块 → 向量化 → 存入向量数据库
2. **查询流程**：用户提问 → 向量化 → 检索相关片段 → 拼接到提示词 → 调用 LLM → 返回答案
3. **核心价值**：无需训练 LLM 就能使用新知识，减少幻觉，可溯源

## 向量数据库在 RAG 中的作用是什么？

1. **存储向量** - 存储文档片段的 Embedding 表示
2. **相似度检索** - 根据问题向量找出最相似的文档片段
3. **常见选型** - Weaviate、Qdrant、Pgvector、Milvus 等

## 文档分块大小如何选择？

1. **一般原则**

   - 太小：信息碎片化，缺少上下文
   - 太大：检索不精确，噪音多
2. **常用设置**

   - 500-1000 字符比较常见
   - 重叠 10-20% 保证连续性
3. **根据内容调整**

   - 代码类：可以稍大
   - 说明文档：可以稍小

## Embedding 模型怎么选？

1. **中文场景推荐**：OpenAI text-embedding-3（通用强）、BGE-M3（开源推荐）、M3E（国产开源）
2. **选型考虑**：准确率、速度、成本、向量维度

## Dify 适合什么场景？

1. **快速原型** - 快速验证想法
2. **非技术团队** - 产品运营可独立使用
3. **知识库问答** - 企业文档问答
4. **客服机器人** - 智能客服系统
