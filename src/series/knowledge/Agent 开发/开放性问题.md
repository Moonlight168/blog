# Agent 开放性问题

开放题没有标准答案，考的是你怎么权衡、有没有真做过，以及能不能讲出取舍的理由。

---

## ⭐ 现在做 Agent 基本有两条路线，一条是把模型的自由度限制住、让它按规则走，一条是把控制权放开、让模型自己发挥，你更偏向哪一种？

我实际做过一点 Agent 之后，我的看法是**这两条不是二选一，关键路径该约束就约束、探索的地方该放开就放开**。但非要让我站一边的话，我更偏向"适度放开 + 关键约束"。

1. **限制路线**：把流程写死、按规则走，模型只在规定好的小范围里做决定。好处是稳定、可控、成本好算、出事好排查，适合审批、RAG 检索、固定流程这类要求正确性和可预期的场景。但天花板低，遇到没覆盖到的边界情况不会变通。
2. **放开路线**：模型自己规划、自己调工具、自己纠正，典型的 Agent 循环。好处是上限高、灵活，能处理开放式任务。但代价是不稳定、token 烧得快、出了问题不好复现。

所以我的实践倾向是：**结果正确性要求高、牵涉钱和权限的步骤，我宁可写死让它按规则走；纯探索、发散、收集信息的步骤，我放给它自己发挥**。举个例子，如果一个 Agent 既要查资料又要替用户下单，那下单这步我必须强约束，查资料那步可以放开。

一句话收尾：约束保证下限，放开决定上限，真正做产品是在这两者之间找平衡点，不是选边站。
