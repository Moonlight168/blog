# Agent 前沿技术面试题

开放问答类：考察对当前 Agent 生态的最新见闻与理解深度，不是背书，重点是"有没有真去了解过、能不能说出自己的判断"。

---

## ⭐ 你还了解过哪些 Agent 吗？除了编码 Agent 外？

编码类的我平时用得比较多，Claude Code、Cursor、Copilot 都有在接触。除了编码的，我最近也确实关注了不少，挑几个说：

1. **WorkBuddy（腾讯）**：被叫"数字员工"，装电脑上免部署，能接微信、飞书、钉钉，OpenClaw 的技能也兼容。像日报汇总、Excel 清洗、会议纪要这种重复性办公活它能直接干，就感觉是把 AI 当同事用。
2. **DeepSeek Harness**：开源智能体框架，口号是"万物皆插件"。最特别的是它把 Claude Code、Codex 这种别的编码 agent 也收编成子代理统一调度，像是想做 Agent 时代的调度层。
3. **Pi Agent**：极简终端编程 agent，走"少即是多"路线，故意不做计划模式，靠 Extension 机制扩展能力，跟 Claude Code 的思路很不一样。
4. **Hermes Agent（Nous Research）**：主打"自进化 + 记忆"，能记住你、越用越了解你，甚至给自己升级，GitHub 十多万 star，被当成 OpenClaw 的强劲对手。
5. **其他生态**：像 LangGraph/LangChain 这些老牌的，Dify 这种工作流平台，还有垂直场景的数字人、营销、客服类 agent，现在也都在快速起量。

它们的差别我觉得主要在"抢的点"不一样：

- **WorkBuddy** 抢的是**入口和办公场景**——先把手伸进微信、飞书这些你天天用的地方；
- **Harness** 抢的是**调度层**——它想当所有 agent 的底座，让别家 agent 都来它这跑；
- **Pi** 抢的是**极简体验**——把终端编程这件事做到最轻；
- **Hermes** 抢的是**自我进化**——靠记忆和自改进让人越用越离不开。

所以现在 Agent 方向已经不只拼单个工具了，更多在拼"底座 + 调度 + 入口 + 记忆"这几个维度，各家取舍不一样。

## 你有用过哪些编码 Agent？它们有什么不同？

用的话主要是 Claude Code、Cursor、GitHub Copilot 这几个，Codex 我也试过，我说下体感。

1. **Claude Code**：终端里的，主打"读整个项目再动手"，Agent 味最重——能自己跑命令、改多个文件、规划步骤，遇到不确定会先问你。适合复杂一点的改动和重构，我平时写后端用得最多。
2. **Codex（OpenAI）**：OpenAI 的 agentic 编程工具，IDE 插件和终端两种形态都有，同样能多步读代码、改文件、跑命令，跟 Claude Code 算同类竞品。
3. **Cursor**：编辑器形态（基于 VS Code），一边写一边给你补全、对话改代码。体验是"帮你写代码"，对新手更友好，补全和 Chat 交互顺滑。
4. **GitHub Copilot**：最早一批，补全很成熟，跟 GitHub 生态（PR、代码库）打通得深。但相对"重补全、轻 Agent"，多步自动改代码不如前面几个。

它们的差别我总结成一句话：**Copilot 是"帮你补全"，Cursor 是"陪你写代码"，Claude Code 和 Codex 是"替你把活干了"**。实际用下来，越是重构、多文件、要决策的活越会交给 Claude Code 这类 agentic 工具，日常写样板代码用 Copilot/Cursor 补全更快。

## DeepSeek Harness 这种"万物皆插件"的思路，和 LangGraph 比有什么不一样？

这俩其实都是 Agent 框架，但官方定位的侧重点不一样，我分开说。

1. **LangGraph 是编排框架**：官方定位是 low-level orchestration framework，把 agent 的流程建成一张图（节点、边、状态、条件路由、循环、human-in-the-loop），怎么决策、怎么流转都在图里显式写。单 agent 和多 agent（supervisor 协作）都支持，核心是给开发者一套"编排语法"。
2. **DeepSeek Harness 是 agent 运行时/harness**：官方定位是 agent harness、agent runtime，主打"万物皆插件"。它自己就能跑 agent（模型、工具、上下文、沙箱都按插件挂），招牌是把 Claude Code、Codex 这种完整的 agent 也收编成子代理，当统一调度层。
3. **一句话区分**：LangGraph 管"agent 的流程怎么编排"（图），Harness 管"agent 怎么跑起来、怎么被统一调度"（插件化运行时）。两个都是底层框架，都不是 WorkBuddy 那种垂直业务 agent。

## 如果让你评估一个办公类 Agent（比如 WorkBuddy 这种"数字员工"）能不能在你们公司落地，你会看哪些点？

我会从四个角度去掂量，毕竟办公 agent 碰的是真实业务和权限。

1. **任务边界**：先看它能不能稳定处理一类具体的活（日报、报表、邮件回复），而不是什么都想做。边界清晰，我才敢让它碰真实数据。
2. **权限与安全**：办公 agent 要读写企业数据，权限得最小化、操作留审计日志，高风险动作（发邮件、删文件、转账）要不要人工确认，这些上线前必须谈清楚。
3. **工具/技能生态**：能不能接公司的系统（OA、钉钉、飞书、内部 API），是自研技能还是靠 MCP、OpenClaw 这类生态兼容。接得越顺，落地成本越低。
4. **评估与兜底**：拿真实场景跑测试集看任务完成率和错误率，同时设计人工介入和回滚。Agent 是不确定系统，偶尔抽风是常态，得有一套 Bad Case 反馈闭环。

总的来说，办公类 agent 落地，技术和场景其实都能解决，真正的门槛在权限、信任和运营这三件事上。
