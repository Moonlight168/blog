## ⭐ 你还了解过哪些 Agent 吗？除了编码 Agent 外？

**锚点**：`办公（WorkBuddy）、调度（Harness）、极简（Pi）、自进化（Hermes）——各抢各的点`

1. **WorkBuddy（腾讯）**：被叫"数字员工"，免部署，接微信/飞书/钉钉，OpenClaw 技能兼容——日报汇总、Excel 清洗、会议纪要这类重复办公活直接干
2. **DeepSeek Harness**：开源智能体框架，口号"万物皆插件"，把 Claude Code、Codex 收编成子代理统一调度，像 Agent 时代的调度层
3. **Pi Agent**：极简终端编程 agent，"少即是多"，故意不做计划模式，靠 Extension 机制扩展
4. **Hermes Agent（Nous Research）**：主打"自进化 + 记忆"，越用越了解你甚至自我升级，十多万 star，OpenClaw 强劲对手
5. **差别在"抢的点"**：
   - WorkBuddy 抢**入口和办公场景**（微信、飞书这些天天用的地方）
   - Harness 抢**调度层**（当所有 agent 的底座）
   - Pi 抢**极简体验**（终端编程做到最轻）
   - Hermes 抢**自我进化**（记忆 + 自改进让人离不开）

现在 Agent 方向不只拼单个工具，更多拼"**底座 + 调度 + 入口 + 记忆**"这几个维度。

## 你有用过哪些编码 Agent？它们有什么不同？

**锚点**：`Copilot 帮你补全，Cursor 陪你写码，Claude Code/Codex 替你把活干了`

1. **Claude Code**：终端形态，读整个项目再动手，Agent 味最重——自己跑命令、改多文件、规划步骤，不确定先问你；适合复杂改动和重构
2. **Codex（OpenAI）**：IDE 插件 + 终端两种形态，同样多步读代码、改文件、跑命令，Claude Code 同类竞品
3. **Cursor**：编辑器形态（基于 VS Code），一边写一边补全、对话改代码——"帮你写代码"，对新手友好
4. **GitHub Copilot**：最早一批，补全成熟，和 GitHub 生态（PR、代码库）打通深；相对"重补全、轻 Agent"

实际使用：重构、多文件、要决策的活交给 Claude Code 这类 agentic 工具，日常样板代码用 Copilot/Cursor 补全更快。

## DeepSeek Harness 这种"万物皆插件"的思路，和 LangGraph 比有什么不一样？

**锚点**：`LangGraph 管流程怎么编排（图），Harness 管 agent 怎么跑起来（插件化运行时）`

1. **LangGraph 编排框架**：low-level orchestration，把 agent 流程建成图（节点、边、状态、条件路由、循环、human-in-the-loop），决策流转在图里显式写；单 agent 和多 agent（supervisor 协作）都支持
2. **DeepSeek Harness agent 运行时/harness**：主打"万物皆插件"，自己就能跑 agent（模型、工具、上下文、沙箱都按插件挂），招牌是把 Claude Code、Codex 收编成子代理当统一调度层
3. **一句话区分**：LangGraph 管"流程怎么编排"，Harness 管"怎么跑起来、怎么被统一调度"；都是底层框架，都不是 WorkBuddy 那种垂直业务 agent

## 如果让你评估一个办公类 Agent（比如 WorkBuddy 这种"数字员工"）能不能在你们公司落地，你会看哪些点？

**锚点**：`四看：任务边界、权限安全、工具生态、评估兜底——门槛在权限和信任`

1. **任务边界**：先看能不能稳定处理一类具体的活（日报、报表、邮件回复），边界清晰才敢让它碰真实数据
2. **权限与安全**：读写企业数据权限最小化、操作留审计日志；高风险动作（发邮件、删文件、转账）人工确认，上线前谈清楚
3. **工具/技能生态**：能不能接公司系统（OA、钉钉、飞书、内部 API），自研还是靠 MCP、OpenClaw 兼容——接得越顺落地成本越低
4. **评估与兜底**：真实场景测试集看任务完成率和错误率；设计人工介入和回滚；Agent 是不确定系统，得有 Bad Case 反馈闭环

总的来说：办公 agent 落地，技术和场景能解决，**真正的门槛在权限、信任和运营三件事**。
