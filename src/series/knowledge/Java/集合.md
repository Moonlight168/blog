## Java中有哪些集合？

**锚点**：`四大类：List 有序可重复 / Set 无序唯一 / Queue 队列 / Map 键值对`

1. **List**：有序、可重复——ArrayList、LinkedList、Vector
2. **Set**：无序、元素唯一——HashSet、TreeSet、LinkedHashSet
3. **Queue**：队列结构，先进先出——LinkedList、PriorityQueue
4. **Map**：键值对，键唯一——HashMap、TreeMap、ConcurrentHashMap

## List, Set, Queue, Map 有什么区别？

**锚点**：`List 有序可重复 / Set 无序唯一 / Queue 先进先出 / Map 键值对`

1. **List**：有序、可重复——ArrayList、LinkedList
2. **Set**：无序、元素唯一——HashSet、TreeSet
3. **Queue**：队列结构，先进先出——LinkedList、PriorityQueue
4. **Map**：键值对存储，键唯一——HashMap、TreeMap

## ArrayList 和 数组 有什么区别？

**锚点**：`数组定长性能高；ArrayList 动态扩容底层数组`

1. **数组**：长度固定、类型单一、性能高
2. **ArrayList**：长度可变、API 丰富、底层基于数组
3. **场景**：数组适合性能敏感定长；ArrayList 适合动态增删

## 为什么要使用集合，如何选择？

**锚点**：`动态扩容 + 功能丰富 + 泛型安全 + 高性能；按数据特点 + 线程环境选`

**使用原因**：动态扩容免预设大小；操作 API 丰富；泛型类型安全；经过优化性能高

**选择方法**：

1. 按数据特点：允许重复用 List、不允许用 Set、键值对用 Map
2. 按线程环境：单线程用非同步集合（ArrayList、HashMap）；多线程用并发集合（ConcurrentHashMap）

## ArrayList 的扩容机制？

**锚点**：`默认 0，首加变 10，满则 ×1.5，Arrays.copyOf 复制`

1. **初始容量**：默认 0（JDK 8+），首次添加扩容为 10
2. **触发条件**：元素数量超过当前容量
3. **扩容公式**：新容量 = 原容量 × 1.5（10 → 15 → 22 → 33）
4. **数组复制**：`Arrays.copyOf()` 复制，性能开销较大
5. **优化**：`new ArrayList<>(初始容量)` 预分配，避免频繁扩容

## Comparable 和 Comparator 的区别

**锚点**：`Comparable 类内定义自然排序（侵入）；Comparator 类外定义临时排序（解耦）`

| 维度 | Comparable | Comparator |
|------|------------|------------|
| 接口定义 | `compareTo()` 自然排序 | `compare()` 临时排序 |
| 耦合度 | 与类绑定，侵入性强 | 与类分离，解耦好 |
| 场景 | 类的默认排序 | 额外规则（逆序、按其他字段） |

```java
// Comparable：类内实现
public class Person implements Comparable<Person> {
    @Override
    public int compareTo(Person other) {
        return this.age - other.age;  // 按年龄升序
    }
}
Collections.sort(people);

// Comparator：外部定义
Comparator<Person> ageComparator = (p1, p2) -> p1.getAge() - p2.getAge();
Collections.sort(people, ageComparator);
```

## HashMap 和 Hashtable 的区别

**锚点**：`HashMap 性能优先线程不安全；Hashtable 全方法加锁已被淘汰`

| 维度 | HashMap | Hashtable |
|------|---------|-----------|
| 线程安全 | ❌ 不安全 | ✔ 方法全 synchronized |
| 性能 | 高（无锁） | 低（有锁） |
| null 支持 | 允许 1 个 null key、多个 null value | 不允许 |
| 继承体系 | AbstractMap | Dictionary（已过时） |
| 替代方案 | — | ConcurrentHashMap |

## HashMap 的底层原理是什么？

**锚点**：`数组 + 链表 + 红黑树；hash 定位、拉链解决冲突、0.75 扩容 2 倍`

1. **底层结构**：数组 + 链表 + 红黑树
2. **定位方式**：`hash(key)` 计算索引定位桶位
3. **冲突解决**：拉链法；链表超阈值（默认 8）转红黑树提升查询
4. **扩容机制**：容量达 `0.75 × size` 触发扩容（2 倍），重新分配节点
5. **非线程安全原因**：多线程扩容可能链表成环、数据覆盖

## HashMap 在 JDK 1.8 做了什么优化？

**锚点**：`头插改尾插防死循环 + 引入红黑树 + 扰动简化`

1. 链表插入从**头插改尾插**——1.7 头插法多线程 resize 会死循环
2. 引入**红黑树**——链表 ≥ 8 且数组 ≥ 64 转树，查询 O(n)→O(log n)
3. hash 扰动简化——从多次位运算简化为**高 16 位异或低 16 位一次**

## ConcurrentHashMap 底层结构与如何保证线程安全？

**锚点**：`Node[] + 链表 + 红黑树；CAS 无锁 + synchronized 桶级锁`

**底层结构**：`Node[]` 数组 + 链表 + 红黑树，JDK8+ 用**桶级锁 + CAS 无锁**替代 JDK7 分段锁。

**线程安全机制**：

1. **CAS 无锁操作**：插入时 CAS 设置节点，避免阻塞
2. **synchronized 桶级锁**：只锁具体桶位，粒度更细
3. **原子计数**：baseCount + CounterCells 高效 size 统计

## 集合中map的遍历方式有哪些？

**锚点**：`EntrySet 效率最高；forEach 最简洁`

| 方式 | 代码 | 特点 |
|------|------|------|
| KeySet | `for (String key : map.keySet())` | 需二次查找，效率低 |
| Values | `for (Integer v : map.values())` | 只能拿 value |
| EntrySet | `for (Map.Entry e : map.entrySet())` | 效率最高，一次拿键值对 |
| Lambda | `map.forEach((k,v) -> ...)` | 简洁，函数式 |

**推荐**：性能优先 EntrySet；简洁优先 forEach。

## HashMap 底层数据结构？什么时候转红黑树，为什么是 8？

**锚点**：`数组+链表+红黑树；≥8 且数组 ≥64 转树；泊松分布概率 0.00000006`

- 底层：**数组 + 链表 + 红黑树**（JDK 1.8+）
- 转树条件：链表长度 **≥ 8** 且数组长度 **≥ 64**；数组小于 64 优先扩容
- 为什么是 8：**泊松分布概率**——hash 冲突达 8 的概率约 0.00000006，极其罕见；小于 8 链表 O(n) 足够，TreeNode 内存占用更大不划算
- 退化：树节点 ≤ 6 时退回链表
