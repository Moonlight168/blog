## 学生类按分数降序、学号升序如何排序？

**锚点**：`分数优先、学号次级：compareTo 里先比分数再比学号`

**方法1：实现 Comparable（类内）**

```java
public class Student implements Comparable<Student> {
    private int id;
    private int score;

    @Override
    public int compareTo(Student o) {
        int r = Integer.compare(o.score, this.score); // 分数降序
        return r != 0 ? r : Integer.compare(this.id, o.id); // 学号升序
    }
}
```

**方法2：Comparator（不改类时使用）**

```java
Collections.sort(list, (a, b) -> a.score != b.score
    ? Integer.compare(b.score, a.score)
    : Integer.compare(a.id, b.id));
```

## 秒杀超卖问题如何解决？

**锚点**：`四层防线：DB 乐观/悲观锁 → Redis 预减 + 分布式锁 → 限流削峰 → 库存预热防重`

1. **数据库层面**：乐观锁 `UPDATE product SET stock = stock - 1 WHERE id = ? AND stock > 0`；悲观锁 `SELECT ... FOR UPDATE`
2. **应用层面**：Redis 预减库存（扣减成功再写库）；Redis/ZooKeeper 分布式锁保证同一商品单请求处理
3. **架构层面**：令牌桶限流、消息队列削峰；分层过滤（前端验证码 → Redis 预减 → 数据库）；异步下单
4. **业务层面**：库存预热、阶梯释放（分批放库存）、token 机制防重复提交
