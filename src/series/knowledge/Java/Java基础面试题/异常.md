## Java 异常体系结构是怎样的？

```
Throwable
├── Error（JVM严重错误）
│   ├── OutOfMemoryError
│   └── StackOverflowError
└── Exception（程序可处理）
    ├── 受检异常（编译时强制处理）
    │   ├── IOException
    │   └── FileNotFoundException
    └── 运行时异常（RuntimeException）
        ├── NullPointerException
        └── ArrayIndexOutOfBoundsException
```

## 什么是 OOM？什么会导致 OOM？

**OOM（OutOfMemoryError）**：JVM 无法申请到足够内存。

| 类型 | 表现 | 常见原因 |
|------|------|---------|
| 堆内存溢出 | `Java heap space` | 对象过多、内存泄漏、大对象 |
| 栈内存溢出 | `StackOverflowError` | 递归无终止、调用链过长 |
| 方法区溢出 | `Metaspace` | 类加载过多、动态代理 |
| 直接内存溢出 | `Direct buffer memory` | NIO 直接内存分配过多 |

## Java 异常处理机制有哪些？

### 1. try-catch-finally
```java
try {
    // 可能异常的代码
} catch (SpecificException e) {
    // 处理特定异常
} finally {
    // 总是执行（资源清理）
}
```

### 2. throw 和 throws
```java
// 手动抛出异常
throw new IllegalArgumentException("参数错误");

// 方法声明抛出异常
public void read() throws IOException { }
```

### 3. try-with-resources（Java 7+）
```java
try (FileInputStream in = new FileInputStream("a.txt")) {
    // 自动关闭资源
} catch (IOException e) { }
```

### 4. 异常链
```java
try {
    // ...
} catch (SQLException e) {
    throw new ServiceException("服务调用失败", e); // 保留原始异常
}
```

## 现代异常处理最佳实践？

| 实践 | 说明 |
|------|------|
| 自定义业务异常 | `BusinessException`、`UserNotFoundException` |
| 全局异常处理 | `@ControllerAdvice` + `@ExceptionHandler` |
| 异常链 | 保留原始异常，方便排查 |
| 函数式处理 | `Optional` 减少 null 判断 |

## 类加载常见异常有哪些？

| 异常 | 类型 | 原因 |
|------|------|------|
| `ClassNotFoundException` | 受检异常 | `Class.forName()` 找不到类 |
| `NoClassDefFoundError` | Error | 编译时存在，运行时找不到 |
| `ClassFormatError` | Error | 类文件格式错误 |
| `UnsupportedClassVersionError` | Error | 类文件版本高于 JVM 版本 |
