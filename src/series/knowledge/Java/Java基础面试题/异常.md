## Java 异常体系结构是怎样的？

**锚点**：`Throwable：Error（JVM 严重错误）+ Exception（可处理：受检/运行时）`

```
Throwable
├── Error（JVM严重错误）
│   ├── OutOfMemoryError
│   └── StackOverflowError
└── Exception（程序可处理）
    ├── 受检异常（编译时强制处理）
    │   ├── IOException
    │   └── FileNotFoundException
    └── 运行时异常（RuntimeException）
        ├── NullPointerException
        └── ArrayIndexOutOfBoundsException
```

## 什么是 OOM？什么会导致 OOM？

**锚点**：`JVM 无法申请足够内存：堆/栈/方法区/直接内存四类`

| 类型 | 表现 | 常见原因 |
|------|------|---------|
| 堆内存溢出 | `Java heap space` | 对象过多、内存泄漏、大对象 |
| 栈内存溢出 | `StackOverflowError` | 递归无终止、调用链过长 |
| 方法区溢出 | `Metaspace` | 类加载过多、动态代理 |
| 直接内存溢出 | `Direct buffer memory` | NIO 直接内存分配过多 |

## Java 异常处理机制有哪些？

**锚点**：`try-catch-finally / throw-throws / try-with-resources / 异常链`

1. **try-catch-finally**：捕获处理特定异常，finally 总是执行（资源清理）
2. **throw 和 throws**：`throw new IllegalArgumentException(...)` 手动抛；方法声明 `throws IOException`
3. **try-with-resources（Java 7+）**：`try (FileInputStream in = ...)` 自动关闭资源
4. **异常链**：`throw new ServiceException("服务调用失败", e)` 保留原始异常

## 现代异常处理最佳实践？

**锚点**：`自定义业务异常 + 全局异常处理 + 异常链 + Optional`

| 实践 | 说明 |
|------|------|
| 自定义业务异常 | `BusinessException`、`UserNotFoundException` |
| 全局异常处理 | `@ControllerAdvice` + `@ExceptionHandler` |
| 异常链 | 保留原始异常，方便排查 |
| 函数式处理 | `Optional` 减少 null 判断 |

## 类加载常见异常有哪些？

**锚点**：`ClassNotFoundException 受检 / NoClassDefFoundError / ClassFormatError / 版本不匹配`

| 异常 | 类型 | 原因 |
|------|------|------|
| `ClassNotFoundException` | 受检异常 | `Class.forName()` 找不到类 |
| `NoClassDefFoundError` | Error | 编译时存在，运行时找不到 |
| `ClassFormatError` | Error | 类文件格式错误 |
| `UnsupportedClassVersionError` | Error | 类文件版本高于 JVM 版本 |
