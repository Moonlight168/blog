## 什么是序列化与反序列化？为什么需要序列化？

**序列化**：将 Java 对象转换为字节流，便于网络传输或持久化存储。
**反序列化**：将字节流恢复为 Java 对象。

**使用场景：**
1. 跨 JVM 通信（分布式系统）
2. 网络传输（Socket、HTTP）
3. 持久化存储（文件、数据库）
4. 缓存存储（Redis）

## 如何实现序列化？

Java 原生通过 `ObjectOutputStream` 和 `ObjectInputStream` 实现：

```java
// 类需实现 Serializable 接口
public class User implements Serializable {
    private static final long serialVersionUID = 1L;
    private int id;
    private String name;
    private transient String password; // 不参与序列化
}

// 序列化
try (ObjectOutputStream out = new ObjectOutputStream(new FileOutputStream("user.ser"))) {
    out.writeObject(user);
}

// 反序列化
try (ObjectInputStream in = new ObjectInputStream(new FileInputStream("user.ser"))) {
    User user = (User) in.readObject();
}
```

## Java 原生序列化有什么缺点？推荐用什么替代？

**缺点：**
1. 无法跨语言
2. 安全漏洞（反序列化攻击）
3. 序列化后体积大

**推荐框架：**
| 框架 | 特点 | 适用场景 |
|------|------|---------|
| Protobuf | 跨语言、高性能、二进制格式 | 分布式系统、微服务 |
| Jackson/FastJson | JSON 格式、易读、使用简单 | HTTP 接口、配置文件 |
| Kryo | 高性能、Java 专用 | 内部服务调用 |

## 如何将对象从一个 JVM 转移到另一个 JVM？

1. **序列化 + 网络/文件传输**：对象 → 字节流 → 网络/文件 → 目标 JVM → 反序列化
2. **RPC 框架**：gRPC、Dubbo，内部自动处理序列化
3. **消息队列**：RabbitMQ、Kafka，异步传输
4. **共享存储**：Redis、数据库，两个 JVM 读写同一数据源
