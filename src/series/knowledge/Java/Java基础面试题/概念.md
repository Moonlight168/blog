## Java 的优势和劣势是什么？

**优势：**

1. **跨平台**：一次编译，到处运行，JVM 做了底层适配，不同操作系统只需对应 JVM 实现。
2. **面向对象**：封装、继承、多态让代码结构清晰、可维护性高、易于扩展。
3. **内存管理完善**：自动垃圾回收，无需手动管理内存，相对更安全。
4. **生态成熟**：类库和框架非常丰富（如 Spring 全家桶），社区庞大，问题容易找到解决方案。
5. **安全性强**：JVM 隔离、字节码校验、类加载机制，让程序更可靠。
6. **并发能力强**：内置线程模型，配合 JUC 包工具完善，处理并发方便。

**劣势：**

1. 运行依赖 JVM，启动速度比原生语言慢。
2. 内存占用相对偏高。
3. 灵活性不如动态语言，开发效率有时受语法限制。

## JVM、JDK、JRE 三者关系？

1. **JVM（Java虚拟机）**：Java 程序运行的环境，负责将字节码解释或编译成机器码执行，提供内存管理、垃圾回收、安全性等功能，是跨平台的核心。
2. **JDK（Java开发工具包）**：开发 Java 程序的工具集合，包含 JVM、编译器（javac）、调试器等开发工具及标准库。
3. **JRE（Java运行时环境）**：Java 程序运行的最小环境，包含 JVM 和类库，不包含开发工具。

因为 Java 程序不是直接跑在操作系统上的，而是跑在 JVM 上。

## 为什么 Java 既是编译型又是解释型语言？

Java 的执行流程是"**先编译、再解释或编译执行**"。

1. **先编译**：Java 源代码 `.java` 会先被编译成 `.class` 字节码，保证可移植性。
2. **再解释/编译执行**：字节码进入 JVM 后，热点代码会被 **JIT 即时编译**成机器码加速执行；非热点代码由**解释器逐行解释**。

因此 Java 采用 **解释器 + JIT 编译器的混合模式**，既保证跨平台，又有较高执行效率。

**编译型语言 vs 解释型语言：**

1. **编译型**：执行前整体编译成机器码，执行快但跨平台性差（如 C、C++）
2. **解释型**：执行时逐行解释，跨平台好但速度慢（如 Python、JavaScript）

## Java 中一个类是如何跑起来的？

1. **类加载**：由类加载器将 `.class` 文件加载进内存，经过 *加载 → 验证 → 准备 → 解析 → 初始化*。
2. **创建对象**：通过 `new` 或反射创建实例，JVM 在堆上分配内存并初始化成员变量。
3. **执行方法**：字节码经由解释执行或 JIT 编译成本地机器码来运行。
4. **生命周期管理**：方法执行完后栈帧出栈，对象无人引用时最终被 GC 回收。

## 接口与抽象类的区别是什么？

| 维度 | 接口 | 抽象类 |
| --- | --- | --- |
| 多继承 | 支持多接口实现 | 不支持类多继承 |
| 方法实现 | 默认方法可有实现，其他必须抽象 | 可包含抽象方法和普通方法 |
| 字段 | 只能有 `public static final` 常量 | 可以有实例变量 |
| 构造方法 | 没有 | 可以有 |
| 用途 | 描述能力（行为规范） | 描述共性（状态 + 行为） |

## 抽象类可以多继承吗？

不能。Java 不允许一个类同时继承多个类，只能实现多个接口。需要多继承功能时，可通过接口组合实现。

## 全局变量和局部变量的区别？

1. **全局变量（成员变量）**：定义在类中、方法外；生命周期长，从对象创建到销毁；有默认初始值。
2. **局部变量**：定义在方法、构造方法或代码块中；生命周期短；没有默认初始值，必须在使用前赋值。

**实例变量的默认值：**

| 数据类型 | 默认值 |
|---------|--------|
| byte/short/int/long | 0 |
| float/double | 0.0 |
| char | '\u0000' |
| boolean | false |
| 引用类型 | null |

## Java 创建对象有哪些方式？

1. **new 关键字**：直接调用构造方法，最常用。
2. **Class.newInstance()**：反射创建，需无参构造（已废弃）。
3. **Constructor.newInstance()**：反射创建，支持有参构造，推荐。
4. **clone()**：需实现 Cloneable 接口，创建副本（浅拷贝）。
5. **反序列化**：将字节流恢复为对象，需实现 Serializable 接口。

## 如何获取私有对象？

1. **getter 方法**：类提供 public 的 getter 方法获取私有字段，符合封装原则。
2. **反射机制**：通过 `getDeclaredField()` + `setAccessible(true)` 绕过 private 限制，破坏封装性，需谨慎使用。

## 浅拷贝和深拷贝的区别是什么？深拷贝如何实现？

**区别：**

| 对比项 | 浅拷贝 | 深拷贝 |
| --- | --- | --- |
| 拷贝范围 | 仅拷贝对象本身 + 基本类型字段 | 连同所有引用类型字段递归拷贝 |
| 引用关系 | 引用字段共享同一对象 | 引用字段完全独立 |
| 互相影响 | 修改引用字段会互相影响 | 各自独立不影响 |

**深拷贝实现方式：**

1. **Cloneable + 重写 clone()**：递归克隆引用字段，适用于结构明确的场景。
2. **序列化/反序列化**：最简单通用，对象需实现 `Serializable` 接口。
3. **手动 new 再复制**：适用于结构简单的场景，灵活但代码量大。

## Java 中的一级缓存、二级缓存、三级缓存有哪些？

1. **一级缓存：CPU Cache（L1/L2/L3）**：硬件层面，速度最快，纳秒级，开发者无法直接控制。
2. **二级缓存：JVM 内部缓存**：如 String 常量池、IntegerCache、类元数据缓存等，JVM 进程内有效。
3. **三级缓存：外部缓存**：如 Redis、Memcached，跨 JVM 共享，避免数据库压力。

## Java 的 I/O 流分为几种？

1. **字节流**：处理二进制数据（图片、视频等），顶层类 `InputStream`/`OutputStream`
2. **字符流**：处理文本数据，需关注编码，顶层类 `Reader`/`Writer`

| 维度 | 字节流 | 字符流 |
| --- | --- | --- |
| 处理数据 | 二进制数据（所有文件） | 文本数据（仅字符文件） |
| 编码依赖 | 无 | 有（需匹配编码如 UTF-8） |
| 核心场景 | 读写图片、视频、压缩包 | 读写文本文件、配置文件 |

## `==` 和 `equals` 的区别？Integer 用哪个比？

- `==`：比**地址**（基本类型比值）
- `equals`：默认比地址，但 String/Integer 重写后比**值**

Integer 用 `equals`，不能用 `==`（-128~127 有缓存，`==` 时对时错）。
