## Java 的优势和劣势是什么？

**锚点**：`跨平台 + 面向对象 + GC + 生态 + 安全 + 并发；劣势：启动慢、内存高、调优难`

**优势**：

1. **跨平台**：一次编译到处运行，JVM 做底层适配
2. **面向对象**：封装、继承、多态，结构清晰、可维护、易扩展
3. **内存管理完善**：自动垃圾回收，无需手动管理
4. **生态成熟**：类库框架丰富（Spring 全家桶），社区庞大
5. **安全性强**：JVM 隔离、字节码校验、类加载机制
6. **并发能力强**：内置线程模型 + JUC 工具

**劣势**：

1. 依赖 JVM，启动速度比原生语言慢
2. 内存占用相对偏高
3. 灵活性不如动态语言
4. 高并发场景需要大量调优——线程池参数、锁粒度（CAS/并发容器替代 synchronized）、GC 选择（G1/ZGC）、JVM 参数、架构层（多级缓存/MQ 削峰/分库分表/限流熔断）

## JVM、JDK、JRE 三者关系？

**锚点**：`JDK ⊃ JRE ⊃ JVM：开发工具包 / 运行环境 / 虚拟机`

1. **JVM（Java 虚拟机）**：程序运行环境，字节码解释或编译成机器码执行，提供内存管理、垃圾回收、安全——跨平台核心
2. **JDK（开发工具包）**：JVM + 编译器（javac）+ 调试器等开发工具 + 标准库
3. **JRE（运行时环境）**：JVM + 类库，不含开发工具

## Java 为什么是跨平台的？

**锚点**：`程序跑在 JVM 上，操作系统差异由不同 JVM 适配`

Java 程序不是直接跑在操作系统上，而是跑在 JVM 上。

常见 JVM：**HotSpot**（最主流，OpenJDK/Oracle 在用）、**OpenJ9**（IBM，内存占用低）、**GraalVM**（多语言、AOT 编译）、**Azul Zing/Zulu**（低延迟高性能）。

## 为什么 Java 既是编译型又是解释型语言？

**锚点**：`先编译成字节码，再解释执行 + JIT 热点编译——混合模式`

1. **先编译**：`.java` → `.class` 字节码，保证可移植性
2. **再解释/编译执行**：热点代码被 **JIT 即时编译**成机器码加速；非热点由**解释器逐行解释**

**对比**：编译型（C/C++）执行快但跨平台差；解释型（Python/JS）跨平台好但慢。

## Java 中一个类是如何跑起来的？

**锚点**：`类加载 → 创建对象 → 执行方法 → GC 回收`

1. **类加载**：类加载器把 `.class` 加载进内存：加载 → 验证 → 准备 → 解析 → 初始化
2. **创建对象**：`new` 或反射创建，堆上分配内存并初始化成员变量
3. **执行方法**：字节码解释执行或 JIT 编译成本地机器码
4. **生命周期管理**：方法执行完栈帧出栈，对象无人引用被 GC 回收

## 接口与抽象类的区别是什么？

**锚点**：`接口描述能力（多实现、常量）；抽象类描述共性（状态+行为、单继承）`

| 维度 | 接口 | 抽象类 |
|------|------|--------|
| 多继承 | 支持多接口实现 | 不支持类多继承 |
| 方法实现 | 默认方法可有实现，其他必须抽象 | 可含抽象方法和普通方法 |
| 字段 | 只能 `public static final` 常量 | 可有实例变量 |
| 构造方法 | 没有 | 可以有 |
| 用途 | 描述能力（行为规范） | 描述共性（状态 + 行为） |

## 抽象类可以多继承吗？

**锚点**：`不能；多继承功能通过接口组合实现`

Java 不允许一个类同时继承多个类，只能实现多个接口。需要多继承功能时，通过接口组合实现。

## 全局变量和局部变量的区别？

**锚点**：`成员变量生命周期长有默认值；局部变量生命周期短必须赋值`

1. **全局变量（成员变量）**：定义在类中方法外；生命周期长（对象创建到销毁）；有默认初始值
2. **局部变量**：定义在方法/构造方法/代码块中；生命周期短；无默认值，使用前必须赋值

**实例变量默认值**：byte/short/int/long → 0；float/double → 0.0；char → '\u0000'；boolean → false；引用类型 → null。

## Java 创建对象有哪些方式？

**锚点**：`new / Class.newInstance()（废弃）/ Constructor.newInstance()（推荐）/ clone / 反序列化`

1. **new 关键字**：直接调用构造方法，最常用
2. **Class.newInstance()**：反射创建，需无参构造（已废弃）
3. **Constructor.newInstance()**：反射创建，支持有参构造，推荐
4. **clone()**：需实现 Cloneable，创建副本（浅拷贝）
5. **反序列化**：字节流恢复对象，需实现 Serializable

## 如何获取私有对象？

**锚点**：`getter 符合封装；反射 getDeclaredField + setAccessible 绕过（慎用）`

1. **getter 方法**：类提供 public getter 获取私有字段，符合封装原则
2. **反射机制**：`getDeclaredField()` + `setAccessible(true)` 绕过 private，破坏封装，需谨慎

## 浅拷贝和深拷贝的区别是什么？深拷贝如何实现？

**锚点**：`浅拷贝引用共享互相影响；深拷贝递归复制完全独立`

| 对比 | 浅拷贝 | 深拷贝 |
|------|--------|--------|
| 拷贝范围 | 对象本身 + 基本类型字段 | 引用字段递归拷贝 |
| 引用关系 | 引用字段共享同一对象 | 完全独立 |
| 互相影响 | 修改会互相影响 | 各自独立 |

**深拷贝实现**：

1. **Cloneable + 重写 clone()**：递归克隆引用字段，结构明确时用
2. **序列化/反序列化**：最简单通用，对象需实现 `Serializable`
3. **手动 new 再复制**：结构简单灵活，但代码量大

## Java 中的一级缓存、二级缓存、三级缓存有哪些？

**锚点**：`CPU Cache（纳秒级）/ JVM 内部缓存（常量池、IntegerCache）/ 外部缓存（Redis）`

1. **一级缓存：CPU Cache（L1/L2/L3）**：硬件层面，纳秒级，开发者无法直接控制
2. **二级缓存：JVM 内部缓存**：String 常量池、IntegerCache、类元数据缓存等，进程内有效
3. **三级缓存：外部缓存**：Redis、Memcached，跨 JVM 共享，减轻数据库压力

## Java 的 I/O 流分为几种？

**锚点**：`字节流（二进制 InputStream/OutputStream）+ 字符流（文本 Reader/Writer）`

| 维度 | 字节流 | 字符流 |
|------|--------|--------|
| 处理数据 | 二进制（所有文件） | 文本（仅字符文件） |
| 编码依赖 | 无 | 有（需匹配编码如 UTF-8） |
| 核心场景 | 图片、视频、压缩包 | 文本文件、配置文件 |

## `==` 和 `equals` 的区别？Integer 用哪个比？

**锚点**：`== 比地址；equals 重写后比值；Integer 用 equals`

- `==`：比**地址**（基本类型比值）
- `equals`：默认比地址，但 String/Integer 重写后比**值**

Integer 用 `equals`，不能用 `==`（-128~127 有缓存，`==` 时对时错）。
