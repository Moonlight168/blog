## 说一下你对 Elasticsearch 的理解？

Elasticsearch 是基于 Lucene 的分布式搜索和分析引擎，核心能力是**全文检索**。

**主要特点**：
1. **分布式**：数据自动分片、副本，支持水平扩展和高可用
2. **近实时**：写入后几乎立刻可查，适合日志、监控场景
3. **搜索和分析能力强**：支持关键词搜索、聚合统计、过滤、排序
4. **接口友好**：RESTful API + JSON，易于集成

**常见场景**：日志检索（ELK）、搜索引擎、电商商品检索、监控报警、实时数据分析。

## 你是如何在项目中使用 Elasticsearch 的？

1. **集成方式**：使用 Spring Data Elasticsearch 或官方 REST 客户端连接集群
2. **数据建模**：业务实体映射为索引，配置分词器和分析器
3. **数据同步**：通过消息队列或定时任务同步数据库变更到 ES
4. **查询分析**：DSL 查询实现搜索、分页、排序；聚合功能做统计分析
5. **优化**：合理设置分片、副本数，热数据缓存

**总结**：数据库存储核心数据，ES 负责快速检索和统计分析。

## Elasticsearch 的倒排索引了解吗？

倒排索引是 ES 高效搜索的核心数据结构。

**原理**：
1. 对文档内容分词，提取词条
2. 记录每个词条出现在哪些文档中
3. 搜索时根据词条快速定位文档

**示例**：
- 文档1：`Elasticsearch 是搜索引擎`
- 文档2：`搜索引擎很有用`

| 词条 | 文档ID |
|------|--------|
| elasticsearch | 1 |
| 搜索引擎 | 1, 2 |
| 有用 | 2 |

**优点**：搜索时间复杂度接近 O(1)，适合全文检索。

## ES 和 MySQL 有什么区别？各适合什么场景？

| 对比项 | Elasticsearch | MySQL |
|--------|---------------|-------|
| 数据结构 | 倒排索引 | B+ 树 |
| 查询类型 | 全文检索、模糊搜索 | 精确匹配、范围查询 |
| 写入性能 | 较慢（需建索引） | 快 |
| 事务支持 | 不支持 ACID | 完整 ACID |
| 适用场景 | 搜索、日志分析、聚合统计 | 核心业务数据、事务处理 |

**最佳实践**：MySQL 存核心数据，ES 做搜索加速，通过同步保持一致。

## Elasticsearch 的分片和副本是什么？

**分片**：
- 将索引数据拆分成多个小块存储
- 水平扩展，分散到多个节点提升性能
- 分片数创建后不可修改

**副本**：
- 分片的复制，提供高可用
- 故障时副本可提升为主分片
- 副本可分担读请求，提升查询性能

**建议**：
- 分片数：单分片 10-50GB，避免过多小分片
- 副本数：生产环境至少 1 个副本

## ES 写入数据的过程是怎样的？

1. 客户端向协调节点发送写请求
2. 协调节点根据 ID 路由到主分片所在节点
3. 写入主分片的内存缓冲区
4. 写入 translog（保证数据不丢失）
5. 定期 refresh 到 segment（近实时可见）
6. 定期 flush 持久化到磁盘

**关键参数**：
- `refresh_interval`：刷新间隔，默认 1 秒
- 写入量大时可适当调大提升性能

## ES 查询数据的过程是怎样的？

1. 客户端向协调节点发送查询请求
2. 协调节点将请求广播到相关分片
3. 各分片执行查询，返回文档 ID 和分数
4. 协调节点合并排序结果
5. 根据文档 ID 向对应分片获取完整文档
6. 返回结果给客户端

**优化点**：
- 使用 filter 不计算分数，可缓存
- 避免深度分页（from + size 过大）

## ES 如何解决深度分页问题？

`from + size` 默认最大 10000，深度分页会导致内存压力。

**解决方案**：

1. **scroll 查询**：类似游标，适合大量数据导出，但占用资源
2. **search_after**：基于上一页最后一条记录排序值获取下一页，适合实时分页

```json
{
  "size": 10,
  "sort": [{"_id": "asc"}],
  "search_after": ["last_doc_id"]
}
```

**推荐**：实时分页用 search_after，数据导出用 scroll。

## Elasticsearch 的文本分析器是什么？

分析器将文本转换为倒排索引的词条。

**组成**：
1. **字符过滤器**：预处理（如去除 HTML 标签）
2. **分词器**：将文本切分为词条
3. **词条过滤器**：处理词条（如转小写、去停用词）

**常用分析器**：
- `standard`：默认，按空格和标点分词
- `keyword`：不分词，整体作为一个词条
- `ik_max_word`：中文分词，细粒度
- `ik_smart`：中文分词，粗粒度

## 如何保证 ES 和数据库的数据一致性？

1. **同步双写**：写数据库同时写 ES，一致性差
2. **异步双写**：写数据库后发 MQ，异步写 ES，最终一致
3. **定时任务**：定期同步增量数据，延迟较高
4. **Binlog 同步**：通过 Canal 监听 MySQL binlog，实时同步

**推荐**：MQ 异步双写或 Canal 监听 binlog。

## ES 集群的脑裂问题是什么？如何解决？

**脑裂**：网络分区导致集群出现多个主节点，数据不一致。

**原因**：
- 网络分区，节点间通信中断
- `minimum_master_nodes` 配置不当

**解决方案**：
1. 设置 `discovery.zen.minimum_master_nodes = N/2 + 1`
2. ES 7.0+ 自动计算该值，无需手动配置
3. 合理设置网络超时参数
4. 部署至少 3 个主节点候选

## ES 的聚合有哪些类型？

1. **指标聚合**：计算统计值，如 sum、avg、max、min、count
2. **桶聚合**：分组统计，如 terms、range、date_histogram
3. **管道聚合**：基于其他聚合结果再聚合

**示例**：按日期分组统计销量
```json
{
  "aggs": {
    "sales_over_time": {
      "date_histogram": {
        "field": "date",
        "calendar_interval": "day"
      }
    }
  }
}
```
