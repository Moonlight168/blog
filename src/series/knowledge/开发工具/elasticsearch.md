## 说一下你对 Elasticsearch 的理解？

**锚点**：`基于 Lucene 的分布式搜索分析引擎，核心是全文检索`

1. **分布式**：数据自动分片、副本，水平扩展 + 高可用
2. **近实时**：写入后几乎立刻可查，适合日志、监控场景
3. **搜索分析强**：关键词搜索、聚合统计、过滤、排序
4. **接口友好**：RESTful API + JSON，易集成

**常见场景**：日志检索（ELK）、搜索引擎、电商商品检索、监控报警、实时数据分析。

## 你是如何在项目中使用 Elasticsearch 的？

**锚点**：`集成 → 建模 → 同步 → 查询 → 优化；DB 存核心，ES 做检索`

1. **集成方式**：Spring Data Elasticsearch 或官方 REST 客户端连接集群
2. **数据建模**：业务实体映射为索引，配置分词器和分析器
3. **数据同步**：MQ 或定时任务同步数据库变更到 ES
4. **查询分析**：DSL 查询做搜索、分页、排序；聚合做统计分析
5. **优化**：合理设置分片、副本数，热数据缓存

**总结**：数据库存储核心数据，ES 负责快速检索和统计分析。

## Elasticsearch 的倒排索引了解吗？

**锚点**：`分词建词条→文档映射，搜索按词条 O(1) 定位`

1. **原理**：对文档内容分词提取词条 → 记录每个词条出现在哪些文档 → 搜索时按词条快速定位
2. **示例**：
   - 文档1：`Elasticsearch 是搜索引擎`；文档2：`搜索引擎很有用`
   - 词条表：elasticsearch→1、搜索引擎→1,2、有用→2
3. **优点**：搜索时间复杂度接近 O(1)，适合全文检索

## ES 和 MySQL 有什么区别？各适合什么场景？

**锚点**：`倒排 vs B+树；搜索分析 vs 事务存储——最佳实践是两者配合`

| 对比项 | Elasticsearch | MySQL |
|--------|---------------|-------|
| 数据结构 | 倒排索引 | B+ 树 |
| 查询类型 | 全文检索、模糊搜索 | 精确匹配、范围查询 |
| 写入性能 | 较慢（需建索引） | 快 |
| 事务支持 | 不支持 ACID | 完整 ACID |
| 适用场景 | 搜索、日志分析、聚合统计 | 核心业务数据、事务处理 |

**最佳实践**：MySQL 存核心数据，ES 做搜索加速，通过同步保持一致。

## Elasticsearch 的分片和副本是什么？

**锚点**：`分片横向扩展（创建后不可改），副本高可用 + 分担读`

1. **分片**：索引数据拆成小块存储，分散到多节点提升性能；分片数创建后不可修改
2. **副本**：分片的复制，故障时可提升为主分片；可分担读请求提升查询性能
3. **建议**：单分片 10-50GB（避免过多小分片）；生产环境至少 1 个副本

## ES 写入数据的过程是怎样的？

**锚点**：`协调节点路由 → 主分片 → 缓冲区 + translog → refresh 可见 → flush 落盘`

1. 客户端向协调节点发送写请求
2. 协调节点根据 ID 路由到主分片所在节点
3. 写入主分片的内存缓冲区
4. 写入 translog（保证数据不丢失）
5. 定期 refresh 到 segment（近实时可见）
6. 定期 flush 持久化到磁盘

**关键参数**：`refresh_interval` 默认 1 秒，写入量大时可适当调大提升性能。

## ES 查询数据的过程是怎样的？

**锚点**：`协调节点广播 → 各分片查 → 合并排序 → 取完整文档`

1. 客户端向协调节点发送查询请求
2. 协调节点将请求广播到相关分片
3. 各分片执行查询，返回文档 ID 和分数
4. 协调节点合并排序结果
5. 根据文档 ID 向对应分片获取完整文档
6. 返回结果给客户端

**优化点**：filter 不计算分数可缓存；避免深度分页（from + size 过大）。

## ES 如何解决深度分页问题？

**锚点**：`实时分页用 search_after，数据导出用 scroll`

`from + size` 默认最大 10000，深度分页会导致内存压力。

1. **scroll 查询**：类似游标，适合大量数据导出，但占用资源
2. **search_after**：基于上一页最后一条记录的排序值取下一页，适合实时分页

```json
{
  "size": 10,
  "sort": [{"_id": "asc"}],
  "search_after": ["last_doc_id"]
}
```

## Elasticsearch 的文本分析器是什么？

**锚点**：`字符过滤器 → 分词器 → 词条过滤器；中文用 ik`

1. **组成**：字符过滤器（预处理，如去 HTML 标签）→ 分词器（切词条）→ 词条过滤器（转小写、去停用词）
2. **常用分析器**：
   - `standard`：默认，按空格和标点分词
   - `keyword`：不分词，整体一个词条
   - `ik_max_word`：中文分词，细粒度
   - `ik_smart`：中文分词，粗粒度

## 如何保证 ES 和数据库的数据一致性？

**锚点**：`推荐 MQ 异步双写或 Canal 监听 binlog`

1. **同步双写**：写库同时写 ES——一致性差，耦合
2. **异步双写**：写库后发 MQ 异步写 ES——最终一致，推荐
3. **定时任务**：定期同步增量——延迟较高
4. **Binlog 同步**：Canal 监听 MySQL binlog 实时同步——推荐

## ES 集群的脑裂问题是什么？如何解决？

**锚点**：`网络分区多主节点 → minimum_master_nodes = N/2 + 1`

1. **脑裂**：网络分区导致集群出现多个主节点，数据不一致
2. **原因**：网络分区通信中断；`minimum_master_nodes` 配置不当
3. **解决**：
   - 设置 `discovery.zen.minimum_master_nodes = N/2 + 1`
   - ES 7.0+ 自动计算该值，无需手动配置
   - 合理设置网络超时参数
   - 部署至少 3 个主节点候选

## ES 的聚合有哪些类型？

**锚点**：`指标（算值）/ 桶（分组）/ 管道（再聚合）`

1. **指标聚合**：计算统计值，如 sum、avg、max、min、count
2. **桶聚合**：分组统计，如 terms、range、date_histogram
3. **管道聚合**：基于其他聚合结果再聚合

**示例**：按日期分组统计销量

```json
{
  "aggs": {
    "sales_over_time": {
      "date_histogram": {
        "field": "date",
        "calendar_interval": "day"
      }
    }
  }
}
```
