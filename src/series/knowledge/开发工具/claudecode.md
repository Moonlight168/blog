## 你是如何使用 AI 工具辅助编程的？

**锚点**：`AI 是副驾驶，你是驾驶员：提效的事交给它，决策的事留给自己`

1. **使用场景**：
   - 需求澄清：让 AI 拆解需求、识别边界条件
   - 代码生成：模板代码、工具函数、测试用例
   - 代码审查：检查潜在 bug、安全漏洞、性能问题
   - 调试排错：分析错误日志，提供排查思路
   - 文档编写：注释、API 文档、提交信息
2. **不依赖 AI 的场景**：
   - 核心业务逻辑设计、架构决策
   - 涉及敏感数据的代码、需要深度理解的复杂算法

**简要记忆**：AI 提效，人做决策。

## AI 生成的代码如何验证可靠性？

**锚点**：`生成只是开始，验证才是关键`

1. **通读理解**：逐行阅读，确保理解每一行的作用
2. **运行测试**：运行现有测试 + 新增测试覆盖
3. **边界检查**：验证空值、异常、边界条件处理
4. **安全审查**：检查 SQL 注入、XSS、命令注入等漏洞
5. **性能评估**：复杂操作是否有性能隐患
6. **人工重构**：按团队规范优化命名和结构

## 如何向 AI 提问才能获得高质量代码？

**锚点**：`背景 + 目标 + 约束 + 示例 = 好代码`

好提示词 5 要素：

1. 背景信息：项目类型、技术栈、已有代码
2. 明确目标：具体要做什么，输入输出是什么
3. 约束条件：性能要求、兼容性、代码规范
4. 示例数据：输入示例、期望输出
5. 迭代反馈：根据输出继续追问优化

```
# 坏提问
帮我写个排序函数

# 好提问
JavaScript 数组排序，按对象 age 字段升序，
要求稳定排序，处理 age 缺失的情况
```

## AI 辅助编程的常见陷阱？

**锚点**：`AI 会犯错，审查不能少`

1. **六大陷阱**：
   - 过度信任：AI 会犯错，必须人工审查
   - 安全漏洞：可能生成不安全的代码模式
   - 依赖幻觉：可能编造不存在的 API
   - 上下文丢失：长对话中可能忘记之前的约定
   - 知识过期：训练数据有截止时间
   - 代码冗余：倾向生成冗长代码
2. **应对策略**：关键代码必须审查；重要 API 查官方文档；定期重置对话上下文；明确告知知识截止时间

## 如何配置 AI 工具适应团队规范？

**锚点**：`规范写下来，AI 才能遵守`

1. **配置文件**：创建 `.claude.md` 或类似规范文件
2. **示例代码**：提供团队代码风格示例
3. **明确约束**：直接告知命名规范、目录结构
4. **Hooks 配置**：自动运行 linter、formatter
5. **持续反馈**：指出不符合规范的地方让其修正
