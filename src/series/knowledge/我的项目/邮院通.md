## 项目概述

邮院通是一个校园综合服务平台，整合了课程查询、成绩查询、社团管理、宿舍服务、校园通知等业务模块，提供统一的校园服务入口。系统集成 AI 智能助手，基于 Ollama + Qwen 大模型和 Dify 知识库实现 RAG（检索增强生成）问答，支持自然语言查询校园信息。

**技术栈：** Spring Boot 3、Spring Security、MyBatis-Plus、MySQL、Redis、Elasticsearch、RabbitMQ、Vue3、TDesign、TailwindCSS、Ollama/Dify

**项目链接：** [GitHub - 邮院通](https://github.com/Moonlight168/campus-ai-assistant)

## 你在项目中如何实现用户鉴权？

在项目中，我使用 Spring Security 实现了用户鉴权模块，配置了 `UsernamePasswordAuthenticationFilter`和`JwtAuthenticationFilter` 两个核心过滤器。

**实现流程：**
1. 用户登录时，通过用户名和密码进行验证
2. 验证通过后，生成 JWT 令牌返回给客户端
3. 客户端在后续请求的 HTTP Header 中携带该令牌
4. 服务器通过 JWT 过滤器解析并验证身份

**技术细节：**
- 不同角色（学生、教师、管理员）使用不同的 JWT 签名密钥
- Token 过期时间设置为 2 小时，支持 Refresh Token 刷新
- 使用 Spring Security 的 `SecurityFilterChain` 配置接口访问权限

3. Spring Security 的过滤器链执行顺序是怎样的？

## 如何保证 Redis 缓存与数据库的数据一致性？

我采用的是"更新数据库后删除缓存"的 Cache-Aside 策略。

**具体做法：**
1. 先更新数据库
2. 然后删除对应的 Redis 缓存
3. 下次查询时缓存未命中，从数据库读取并重新写入缓存

**优化措施：**
1. 设置缓存过期时间（如新闻缓存 1 小时自动失效）
2. 对关键数据使用双删策略（先删缓存→更新 DB→延时再删缓存）
3. 通过 RabbitMQ 异步处理缓存更新，削峰填谷

**追问：**
1. 为什么选择"删缓存"而不是"更新缓存"？（避免并发写冲突）
2. 什么是缓存穿透、缓存击穿、缓存雪崩？如何解决？
3. 如果删除缓存失败，如何保证最终一致性？
4. Redis 的 RDB 和 AOF 持久化机制如何选择？

在项目中，我使用 Elasticsearch 对课程、新闻、通知等数据建立全文索引，实现关键词搜索和模糊查询。

**应用场景：**
1. 校园新闻、公告的全文检索
2. 课程信息、社团信息的模糊查询

2. 通过 ES 检索相关的知识库文档
3. 将检索结果拼接到 Prompt 中

## AI 智能助手是如何实现的？RAG 的原理是什么？

AI 智能助手基于 Ollama 部署的 Qwen 大模型，结合 Dify 平台实现知识库管理。

**RAG（检索增强生成）原理：**
1. 先从知识库（Elasticsearch）检索与问题相关的上下文
2. 将检索结果拼接到 Prompt 中
3. 交给 LLM 生成回答

**优势：**
1. 减少 LLM 幻觉，提高回答准确性
2. 可以利用私有知识库（校规、选课手册等）
3. 无需重新训练模型即可更新知识

**技术实现：**
- Redis 存储对话上下文，支持多轮对话
- Elasticsearch 提供语义检索能力
- Ollama 本地部署 Qwen 模型，支持离线推理

3. 向量数据库（如 Milvus）的工作原理？

## 项目中遇到过什么技术难点？如何解决的？

**1. 高并发场景下的缓存一致性问题**

在抢课等高并发场景下，通过 Redis 分布式锁 + 数据库乐观锁保证数据一致性。

**2. 搜索相关性优化**

通过 ES 的自定义分词器、同义词词典、权重配置提升搜索结果相关性。

**3. AI 回答幻觉问题**

引入 RAG 技术，通过知识库检索约束 LLM 的发散性，提升回答准确性。

**4. 前后端联调问题**

通过 Torna 接口管理平台实现 API 文档自动生成，减少沟通成本。
