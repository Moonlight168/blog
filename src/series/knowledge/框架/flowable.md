## Flowable 是什么？为什么不用硬编码状态机做审批？

**锚点**：`开源 BPMN 工作流引擎，把流程逻辑从代码里抽出来 → 可视化定义 + 引擎驱动流转 + 支持驳回会签`

1. **定位**：Java 开源工作流引擎，按 BPMN 2.0 标准定义和执行流程
2. **对比硬编码状态机**：状态机改流程要改代码重新发版；Flowable 改流程图即可生效，业务人员也能看懂流程
3. **自带能力**：任务分配、会签、驳回、条件网关、历史流程查询，不用自己实现
4. **适用场景**：审批流、工单流、合同流等有明确环节流转的业务

## Flowable 核心概念：流程定义、流程实例、任务是什么关系？

**锚点**：`定义=图纸，实例=按图纸开的工，任务=当前该谁干活`

1. **流程定义（ProcessDefinition）**：部署的流程图（bpmn.xml），静态模板，一个流程一套
2. **流程实例（ProcessInstance）**：按定义启动的一次执行，一条业务申请对应一个实例
3. **任务（Task）**：实例流转到当前节点产生的待办，绑定具体审批人
4. **流程变量（Variable）**：实例级数据（申请内容、审批结果），驱动网关分支走向

## 一个审批流程从创建到走完的完整过程？

**锚点**：`部署 bpmn → 按 businessKey 启动实例 → 查任务 → 完成任务流转 → 网关分支 → 结束`

1. **部署**：repositoryService 把 bpmn20.xml 部署为流程定义（发布后才生效）
2. **启动**：runtimeService.startProcessInstanceByKey(流程key, businessKey)，businessKey 关联业务单号
3. **流转**：审批人 taskService.complete(taskId)，引擎自动推进到下一节点
4. **分支**：排他网关按流程变量判断走向（同意→下一节点 / 驳回→回退）
5. **历史**：historyService 查已办、流程轨迹，支持审批记录展示

## FlowMind 里怎么集成 Flowable 的？

**锚点**：`RuoYi-Cloud 引入依赖 → 设计并发布流程定义 → 发起审批启动实例 → 审批中心任务流转 → 历史记录查询`

1. **集成**：RuoYi-Cloud 微服务引入 Flowable 依赖，配好数据源，引擎启动自动建流程相关表
2. **流程管理**：设计审批流程（BPMN）→ 发布 → 生效，业务侧按流程 key 发起申请
3. **审批中心**：查待办任务、完成任务（同意/驳回）、审批记录与流程查询
4. **AI 联动**：LangGraph 解析自然语言生成流程节点与表单配置，落地为 Flowable 流程定义和表单，实现自然语言发起审批
