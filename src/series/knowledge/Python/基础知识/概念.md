## Python 是解释型还是编译型语言？

**锚点**：`解释型，但先编译成字节码再交给 PVM 执行`

1. **执行流程**：源代码 (.py) 编译为字节码 (.pyc) → Python 虚拟机 (PVM) 解释执行字节码
2. **对比**：
   - 解释型：调试容易、速度较慢、跨平台容易
   - 编译型：执行快、需重新编译

## 什么是 GIL（全局解释器锁）？

**锚点**：`CPython 解释器级互斥锁：不用手动加锁，同一时刻也只有一条线程在执行字节码`

1. **是什么**：CPython 解释器自带的全局锁，锁的是"执行字节码"这个动作；不像 Java 的 `synchronized` 要自己加，GIL 是强制的，一行锁都不写也串行
2. **与 Java 锁的区别**：
   - Java 锁：程序员主动加，粒度可控，没加锁的代码多线程真并行（用满多核）
   - GIL：解释器强制、全局唯一，CPU 密集时多线程永远跑不满多核
3. **使用场景**：
   - CPU 密集型：受限制，多线程退化成串行，开了也白开
   - I/O 密集型：不受影响，线程等 I/O 时释放 GIL，多线程能提并发
4. **怎么用**：
   - CPU 密集 → `multiprocessing` 多进程（每进程独立 GIL）
   - I/O 密集 → 多线程或 `asyncio` 协程
   - 极致性能 → C 扩展释放 GIL，或 CPython 3.13 free-threaded 模式

## Python 的内存管理机制？

**锚点**：`引用计数为主 + 垃圾回收处理循环引用 + 内存池减开销`

1. **引用计数（主要）**：每个对象维护引用计数，为 0 时释放
2. **垃圾回收（辅助）**：处理循环引用
3. **内存池管理**：小对象使用内存池减少开销

```python
a = [1, 2, 3]  # 引用计数=1
b = a          # 引用计数=2
del a          # 引用计数=1
del b          # 引用计数=0，释放
```

## 深拷贝与浅拷贝的区别？

**锚点**：`浅拷贝只复制第一层，深拷贝递归复制完全独立`

1. **浅拷贝**：只复制第一层，嵌套对象共享引用
2. **深拷贝**：递归复制所有嵌套对象，完全独立

```python
import copy
original = [1, [2, 3]]
shallow = copy.copy(original)    # 嵌套共享
deep = copy.deepcopy(original)   # 完全独立
```
