## 如何提升前端性能？

**锚点**：`减请求 + 压缓存 + 异步加载`

1. **减少 HTTP 请求**：合并 CSS/JS、雪碧图、图片压缩
2. **启用压缩与缓存**：开 Gzip、设置合理缓存策略
3. **异步加载**：非关键资源懒加载、异步加载

## JS 和 TS 的区别？

**锚点**：`JS 动态类型灵活易错，TS 超集加静态类型更安全规范`

1. **JS**：动态类型，灵活但类型写错运行期才发现
2. **TS**：JS 的超集，加静态类型与编译期检查，更安全规范
3. **落地**：最终编译成 JS，适合大型/多人项目

## 浏览器 HTTP 缓存了解吗？强缓存和协商缓存有什么区别？

**锚点**：`强缓存不发请求（200 from cache），协商缓存发请求问服务器（304）`

1. **强缓存**：没过期直接用本地副本，**不发请求**
   - 响应头 `Cache-Control: max-age=3600`（HTTP/1.1 推荐）或 `Expires`（HTTP/1.0）
2. **协商缓存**：带验证信息问服务器，没变返回 **304**，变了返回 200 + 新资源
   - `ETag/If-None-Match` 优先于 `Last-Modified/If-Modified-Since`
3. **后端为什么关心**：静态资源缓存直接影响加载速度与带宽；配置不当会出现"改了代码用户还是旧页面"
4. **配合**：`no-cache`=每次协商，`no-store`=不缓存

## CDN 是什么？

**锚点**：`分布式网络：静态资源缓存到离用户最近的节点`

1. **作用**：就近取资源减延迟、降源站压力、节点故障自动切换
2. **流程**：请求静态资源 → DNS 解析到最近节点 → 有缓存直接返回，无缓存回源并缓存

## 什么是闭包？

**锚点**：`函数执行完，它用过的变量还活着——因为内部函数还引用着`

1. **是什么**：内部函数引用外部函数变量，外部执行完变量仍被持有
2. **示例**：`function outer(){ let n=0; return () => ++n }`
   - 调用后 `n` 不被回收，每次调用累加
3. **常见用途**：防抖的计时器、数据私有化（对外只暴露 get/set）

## JS 是单线程的，如何实现异步？

**锚点**：`事件循环：异步任务交环境，完成后回调进任务队列，主线程空闲再执行`

1. **为什么单线程**：JS 要操作 DOM，多线程会竞态，所以主线程一次只干一件事
2. **如何异步**：同步代码先执行，异步回调进任务队列，主线程空闲后按序取
   - `setTimeout(()=>console.log(2),0)` 会排在同步的 1、3 之后
3. **宏任务 vs 微任务**：微任务（`Promise.then`）优先级更高，清空后才取下一个宏任务

## 常用的 HTTP 状态码有哪些？

**锚点**：`2xx 成功 / 3xx 重定向 / 4xx 客户端错 / 5xx 服务器错`

1. **2xx**：200 成功，201 创建，204 无内容
2. **3xx**：301 永久重定向，302 临时，304 缓存未修改
3. **4xx**：400 请求错，401 未授权，403 禁止，404 不存在
4. **5xx**：500 服务器错，502 网关错，503 服务不可用

## 为什么前端请求后端会存在跨域问题？

**锚点**：`源=协议+域名+端口（住址）；跨域=去别人家；浏览器挡读不挡发`

1. **同源=自己家**：协议+域名+端口都一样，调自己的后端 → 畅通
   - 例：页面 `localhost:8080` 调 `localhost:8080/api` 没问题
2. **跨域=去别人家**：三者有一个不同就算跨域
   - 例：页面在 `8080`，后端在 `9001`，端口不同 = 跨域
3. **为什么管**：你登录过银行(bank)，浏览器记住了"发给 bank 的请求要自动带你的登录凭证(cookie)"
   - 若放任跨域乱读，恶意网站就能偷看 bank 返回给你的数据（如余额）
4. **恶意网站怎么借身份**：cookie 是"发给哪个网站就带哪个网站的"，跟你现在在哪个网页无关
   - 恶意网站发请求给 bank → 浏览器自动带上你的 bank cookie → bank 以为是你本人
5. **浏览器只挡"读"**：请求其实发出去了，只是**返回不让跨域页面读**，所以报错其实是浏览器拦的
   - 借身份发请求(CSRF) 浏览器挡不住 → 后端要自己防：校验 Origin/Referer、CSRF Token、Cookie 设 `SameSite`

## 跨域的解决方案有哪些？

**锚点**：`后端点头(CORS) / 骗过浏览器(代理) / 天生不拦(JSONP/WebSocket)`

1. **CORS（正规做法）**：后端在响应头告诉浏览器"这个源可以读" → `Access-Control-Allow-Origin`
   - 前后端分离、网关方案常用
2. **代理（绕开限制）**：让浏览器只请求自己的同源地址，由后端/网关转发到目标
   - 开发用 Vite/webpack proxy，生产用 Nginx 反向代理
3. **JSONP（老办法）**：借 `<script>` 标签不受同源限制，只支持 GET，现在少用
4. **WebSocket / postMessage**：协议本身不受同源限制


## 箭头函数和普通函数的区别？

**锚点**：`无自己的 this（继承外层）、不能 new、语法简洁`

1. 没有自己的 `this`，继承外层作用域
2. 不能 `new`，不能当构造函数
3. 语法更简洁：`const add = (a, b) => a + b`

## 防抖和节流是什么？

**锚点**：`防抖停止后才执行，节流间隔执行`

1. **防抖**：停止触发后才执行，适合点提交只触发最后一次
2. **节流**：按固定间隔执行，适合滚动加载（500ms 内最多一次）

## 前端存储有哪些方式？

**锚点**：`Cookie 4KB / LocalStorage 5MB 永久 / SessionStorage 关页清 / IndexedDB 大容量`

1. **Cookie**：约 4KB，每次请求自动带，适合存会话
2. **LocalStorage**：约 5MB，永久，标签页共享
3. **SessionStorage**：约 5MB，关页面清除
4. **IndexedDB**：浏览器数据库，存大量数据

## 什么是 XSS 攻击，如何防范？

**锚点**：`注入恶意脚本；防：过滤输入 + textContent + CSP + HttpOnly`

1. **是什么**：攻击者在网页注入恶意脚本，用户访问时执行
2. **防范**：
   - 输入过滤特殊字符
   - 输出用 `textContent` 代替 `innerHTML`
   - CSP 响应头限制脚本来源
   - Cookie 加 `HttpOnly`
