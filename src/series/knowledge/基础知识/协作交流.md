## 开发中如果遇到超出自身能力的任务，如何处理？

**锚点**：`上报困难 + 给方案 + 拆解推进 + 过程透明，别硬撑`

* **第一时间向上级说明困难及原因**，明确指出该问题已超出当前能力范围，同时询问任务优先级与时间要求。
* **提出可行方案**：如需要同事协助、需要更多时间学习、或调整任务分配。
* **对任务进行拆解**：将能完成的部分先推进，剩余难点与上级确认处理方案。
* **过程透明**：每日同步进度和卡点，让上级随时掌握情况，避免因盲目硬撑导致延期。
* **若任务紧急，可由更熟悉的同事处理**，但我会在旁参与学习，确保下次遇到类似问题时能够独立解决。

**重点：主动沟通 + 自主解决 + 明确反馈。**

## **如果上级建议你借助 AI 解决不理解的问题，你会怎么做？**

**锚点**：`先自整理再问 AI、理解优先别依赖；仍卡反馈上级，解完沉淀`

* **确认使用环境**：先确认公司是否允许访问外部 AI，或需使用内网 AI。
* **先自行整理问题**：将报错、上下文、预期行为、已尝试方案梳理清晰，再向 AI 提问，提高效率。
* **若仍未解决，及时反馈上级**：说明 AI 的建议、自己的尝试过程、卡点位置，让上级准确判断下一步方案。
* **持续沉淀**：将解决过程整理成笔记或知识点，避免重复踩坑，提升后续独立解决能力。

**核心：用 AI 做“助力”，而不是完全依赖；理解问题比得到答案更重要。**

## 怎么对待加班？

**锚点**：`加班=有目的非常态：紧急/未完成主动加，效率优先、合理沟通、注意平衡`

**回答：**
我认为加班应该是一种有目的、有价值的行为，而非常态。我的态度是：

* **工作优先**：如果是因为项目紧急或自身工作未完成，我会主动加班，确保任务按时交付。
* **效率第一**：通过优化工作方法和时间管理，提高日常工作效率，减少不必要的加班。
* **合理沟通**：如果长期加班影响工作质量和身心健康，我会与上级沟通，共同寻找解决方案（如调整任务量、优化流程）。
* **主动学习**：利用加班时间学习新技术或深入研究工作中的难题，提升自身能力。
* **注重平衡**：在保证工作质量的前提下，合理安排休息时间，保持身心健康，避免 burnout。

**核心：效率优先，价值导向，合理平衡。**

## 怎么对待出差？

**锚点**：`积极配合 + 充分准备 + 及时汇报 + 总结沉淀`

**回答：**
出差是工作的一部分，我会以积极的态度对待：

* **主动配合**：如果出差是为了项目推进、客户沟通或团队协作，我会主动配合安排。
* **充分准备**：出差前做好充分准备（如工作内容、资料、行程安排），提高出差效率。
* **注重沟通**：出差期间保持与团队的密切沟通，及时汇报工作进展和遇到的问题。
* **总结沉淀**：出差结束后，整理出差成果和经验教训，与团队分享，形成知识库。
* **合理安排**：在保证工作质量的前提下，合理安排出差期间的休息时间，照顾好身心健康。

**核心：积极配合，高效执行，注重总结。**

## 工作中怎么跟 AI 协作？有什么要注意的？

**锚点**：`流程闭环 + 多确认 + 不盲信 + 好 Prompt + 验证再合入`

1. **流程闭环**：讨论需求 → 输出方案 → 确认方案 → 输出实现计划 → 确认计划 → 执行 → Code Review。
2. **多确认**：AI 理解偏差是常态，最好让 AI 先输出它理解的方案给你确认，而不是重复说需求。
3. **不盲信**：AI 代码每一行都要人工审查，特别是 SQL（LIMIT）、金额（BigDecimal）、线程安全。
4. **好 Prompt = 好产出**：描述越具体（指定技术栈、约束、边界），AI 产出越可用。
5. **验证闭环**：AI 生成的代码本地跑通测试，不直接合入。

## ⭐上级很忙没及时回复你，但你又很着急，怎么办？

**锚点**：`先判断紧急度：能等就等，阻塞就群里升级再补同步`

1. 先看是不是真的紧急——会不会阻塞今天的工作、有没有对外承诺的时间点
2. 不紧急就先做能推进的部分，等组长回复了再补
3. 真卡住就直接在群里 @ 相关人，或找产品经理先把需求定下来
4. 事后把结论同步给组长，避免绕级沟通造成信息断层

**锚点**：`功能点进 → 方案文档出 → 按痛点、取舍、结果展开`

1. 平时组长只交代功能点，需求分析和方案设计由我自己做
2. 我的习惯是先出方案文档给组长确认，确认后再动手写代码，不过度设计
3. 讲创新点按"原来的痛点 → 常见做法的问题 → 我换的做法 → 结果"来说
4. 例子：批量发通知同步调上游会超时卡死前端，我拆成落库待发送 + 定时扫描 + 异步发送回写状态

## ⭐你的薪资期望是多少？

**锚点**：`报期望值 + 可接受值，不说"最低"`

1. 提前想好两个数：期望值，和一个自己确实能接受的下限
2. 只说"期望 X，可以接受 Y"，不说"最低可以接受 Y"
3. "最低"一出口就成了对方压价的起点，等于自己把价位钉死
4. 被继续压就守住：这是我的可接受范围，再低比较难安排

## ⭐最快什么时候能到岗？

**锚点**：`给确定日期，不要答"再考虑一下"`

1. 先和现团队确认交接周期，算清能脱身的时间点
2. 回答给具体时间，比如"X 月 X 日前可以到岗"
3. 确实定不了就给时限："确认后 3 个工作日内答复"
4. 答"再考虑一下"会让 HR 拿不到确定性，影响推进
