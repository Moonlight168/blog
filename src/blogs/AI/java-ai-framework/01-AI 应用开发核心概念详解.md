# AI 应用开发核心概念详解

> **术语说明**
> | 名词 | 全称 | 中文释义 |
> |------|------|----------|
> | LLM | Large Language Model | 大语言模型 |
> | RAG | Retrieval-Augmented Generation | 检索增强生成 |
> | Embedding | Embedding | 词嵌入/向量化 |
> | Token | Token | 词元/令牌 |
> | ANN | Approximate Nearest Neighbor | 近似最近邻搜索 |
> | MMR | Maximal Marginal Relevance | 最大边界相关 |
> | HyDE | Hypothetical Document Embeddings | 假设文档嵌入 |
> | API | Application Programming Interface | 应用程序接口 |
> | Metrics | Metrics | 指标/度量 |

本文介绍 AI 应用开发的核心概念和技术流程。

## 一、LLM 交互基础

### 1.1 ChatModel 与 Completion

- **ChatModel（对话模型）**：基于消息的交互，支持系统消息、用户消息、助手消息
- **Completion（补全模型）**：给定前缀文本后继续生成

### 1.2 Streaming 流式输出

流式输出逐步返回内容，提升用户体验：

```
用户提问 → 模型开始生成 → 逐字返回 → 完整响应
```

优势：降低等待焦虑、支持实时中断、减少首字节延迟

### 1.3 Prompt 模板

预定义的提示结构，用于规范化和复用：

```
模板：请作为{role}，回答关于{topic}的问题
最终：请作为技术专家，回答关于微服务架构的问题
```

## 二、Embedding 模型与文本向量化

### 2.1 什么是 Embedding

将文本转换为数值向量，语义相似的文本在向量空间中距离更近。

### 2.2 常用 Embedding 模型

| 模型 | 维度 | 特点 | 适用场景 |
|------|------|------|----------|
| BGE-small-zh | 512 | 中文优化，轻量级 | 中文知识库 |
| all-MiniLM-L6-v2 | 384 | 英文优化，速度快 | 英文文档 |
| 通义 Embedding | 1536 | 中英双语 | 通用场景 |
| text-embedding-3-small | 1536 | OpenAI 官方 | 国际化应用 |

### 2.3 应用场景

语义搜索、文档相似度计算、RAG 检索、文本聚类分析

## 三、RAG 核心流程

RAG（Retrieval-Augmented Generation，检索增强生成）是 AI 应用的核心架构。

### 3.1 完整流程

```
Document Loading → Chunking → Embedding → Vector Store → Retrieval → Generation
```

### 3.2 Document Loading（文档加载）

- 本地文件（PDF、Word、Markdown、TXT）
- 数据库、Web 页面、API 接口

### 3.3 Chunking（文本分块）

| 方式 | 说明 | 特点 |
|------|------|------|
| 固定大小分块 | 按字符/token 数切分 | 简单高效，可能切断语义 |
| 语义分块 | 按段落/句子边界切分 | 保持语义完整 |
| 递归分块 | 多层次切分 | 保留文档层次结构 |

### 3.4 Vector Store（向量存储）

| 向量数据库 | 特点 | 适用场景 |
|-----------|------|----------|
| Chroma | 轻量级，易部署 | 开发测试、小型项目 |
| PGVector | PostgreSQL 扩展 | 已有 PG 数据库的项目 |
| Milvus | 专业向量数据库 | 大规模向量检索 |
| Qdrant | Rust 编写，高性能 | 高并发场景 |
| Pinecone | 托管服务 | 免运维需求 |
| Weaviate | 支持混合搜索 | 需要关键词 + 向量搜索 |
| InMemory | 内存存储 | 演示、测试 |

### 3.5 Retrieval（检索）策略

**相似度检索**：余弦相似度、欧几里得距离、点积相似度

**高级检索技术**：
- **Re-rank（重排序）**：初步检索后使用更精确的模型重新排序
- **MMR**（Maximal Marginal Relevance，最大边界相关）：平衡相关性和多样性
- **HyDE**（Hypothetical Document Embeddings，假设文档嵌入）：先生成假设答案，再用假设答案检索

## 四、生产化关注点

| 关注点 | 说明 |
|--------|------|
| Token 限流 | 设置每分钟/每小时 Token 消耗上限 |
| 成本监控 | 记录每次调用的 Token 消耗，设置预算告警 |
| Prompt 注入防护 | 过滤恶意指令，使用系统消息隔离 |
| 降级策略 | 模型不可用时的备选方案，缓存热点问答 |
| 缓存机制 | 缓存相似问题的答案，减少重复 API 调用 |
| 可观测性 | 日志记录、Metrics 指标、链路追踪 |

## 五、总结

AI 应用开发的核心在于理解 LLM 的能力边界，并通过 RAG、Tool Calling、Memory 等技术扩展模型能力。掌握这些核心概念后，可以选择合适的框架（如 LangChain4j 或 Spring AI）进行具体实现。
