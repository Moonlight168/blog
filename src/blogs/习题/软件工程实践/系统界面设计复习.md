## 一、系统界面设计与系统质量有什么关系？应该注意哪些原则

### 界面设计 vs 系统质量

> **界面是用户与系统交互的唯一窗口**，界面质量直接影响用户对系统质量的**主观感受**。

| 系统质量指标 | 界面设计的影响 |
|---|---|
| 可用性（Usability） | 界面是可用性的**最直接体现** |
| 用户满意度 | 界面美观 / 易用 → 满意度高 |
| 学习成本 | 友好界面 → 学习成本低 |
| 操作效率 | 合理的交互 → 提升效率 |
| 错误率 | 校验、提示、防错 → 降低错误率 |
| 可维护性 | 良好的设计模式 → 易于扩展 |

> **结论**：界面设计**不是装饰**，而是**系统质量的核心组成部分**。一个功能强大但界面难用的系统，用户会认为是「质量差」。

## 二、界面设计原则有哪些

> 业界公认的几大界面设计原则，结合人机交互（HCI）理论。

### 七大黄金原则（Shneiderman 法则）

| # | 原则 | 含义 |
|---|---|---|
| 1 | 一致性（Consistency） | 相同操作产生相同结果；颜色、布局、术语保持一致 |
| 2 | 允许撤销操作（Undo） | 用户可随时撤销，避免误操作的恐惧 |
| 3 | 提供反馈（Feedback） | 每个用户操作都有**及时、可见**的系统响应 |
| 4 | 设计良好的对话（Dialog） | 信息流清晰、操作步骤明确 |
| 5 | 预防错误（Error Prevention） | 设计上**避免错误发生**（比错误处理更好） |
| 6 | 允许重做（Reversibility） | 操作可重复、可撤销 |
| 7 | 减轻记忆负担（Reduce Memory） | 减少用户短期记忆：默认值、自动完成、图标化 |

### Norman 的十大交互原则

| 原则 | 含义 |
|---|---|
| 可见性（Visibility） | 系统状态可见 |
| 匹配（Match） | 系统行为符合用户预期 |
| 反馈（Feedback） | 操作立即得到响应 |
| 约束（Constraint） | 限制非法操作 |
| 映射（Mapping） | 控件与功能自然对应 |
| 一致性（Consistency） | 同类操作行为一致 |
| 可恢复性（Recovery） | 支持撤销 / 重做 |
| 指导性（Affordance） | 控件外观提示其功能 |
| 简洁性（Simplicity） | 任务结构清晰 |
| 可发现性（Discoverability） | 功能易于找到 |

### 国内常见的界面设计原则（八条）

| # | 原则 | 说明 |
|---|---|---|
| 1 | 用户导向 | 以用户为中心 |
| 2 | 简洁明了 | 不堆砌元素，突出重点 |
| 3 | 一致性 | 视觉 / 行为 / 用词一致 |
| 4 | 反馈及时 | 操作响应快 |
| 5 | 容错性强 | 错误可恢复、有提示 |
| 6 | 布局合理 | 信息层次清晰、视觉流自然 |
| 7 | 色彩协调 | 符合品牌 / 场景 |
| 8 | 可访问性 | 适配不同用户（视障 / 色盲 / 老龄） |

### 界面设计的详细原则（高频考点）

**布局原则**

| 原则 | 内容 |
|---|---|
| F 形 / Z 形视觉流 | 重要内容放在视觉路径上 |
| 分组（Grouping） | 相关元素靠近，形成视觉单元 |
| 对齐（Alignment） | 元素严格对齐（左 / 右 / 居中） |
| 留白（Whitespace） | 适当的留白提升可读性 |
| 层次（Hierarchy） | 标题、字段、说明的视觉权重分明 |

**输入设计原则**

| 原则 | 内容 |
|---|---|
| 减少输入 | 自动填充、下拉、单选替代手动输入 |
| 默认值 | 给出合理默认值 |
| 实时校验 | 输入即校验，错误即时提示 |
| 格式约束 | 输入框限定类型（手机号、邮箱） |
| 防错 | 必填项标星、关键操作二次确认 |

**输出设计原则**

| 原则 | 内容 |
|---|---|
| 信息清晰 | 表头明确、单位齐全 |
| 避免信息过载 | 分页 / 折叠 / 渐进展示 |
| 重要信息突出 | 颜色 / 粗体 / 位置 |
| 一致的格式 | 日期、数字格式统一 |

**错误处理原则**

| 原则 | 内容 |
|---|---|
| 错误信息明确 | 告诉用户**发生了什么**、**为什么**、**怎么办** |
| 语气友好 | 不要责备用户 |
| 错误可恢复 | 提供撤销 / 重试路径 |
| 错误可定位 | 高亮出错字段 |

**颜色与字体**

| 元素 | 建议 |
|---|---|
| 主色调 | 1~2 种品牌色 |
| 对比度 | 文字与背景对比度 ≥ 4.5:1（WCAG） |
| 字体 | 中文：思源黑体 / 苹方；英文：Inter / Roboto |
| 字号 | 正文 14~16px，标题更大 |
| 色盲友好 | 不仅依赖颜色区分信息（结合图标 / 文字） |

## 三、如何将类图转化为数据库表结构（难点 / 考点）

> 这是数据库设计中的**关键映射**，在「[数据库设计复习](./数据库设计复习.md)」中已有详细展开。

### 核心映射规则速查

| 类图元素 | 映射为 | 备注 |
|---|---|---|
| 类 | 表 | 表名常用复数 |
| 属性 | 列 | 类型对应 |
| 方法 | 不映射 | 存于应用层 |
| 1:1 联系 | 任一端加 FK + UNIQUE | — |
| 1:N 联系 | N 端加 FK | — |
| M:N 联系 | **新建中间表** | 含两端 PK + 联系属性 |
| 继承（泛化） | 三种策略 | 单表 / 具体表 / 类表 |

### 转换步骤总结（速记口诀）

> **类 → 表，属性 → 列；**
> **1:1 / 1:N → 外键挂多端；**
> **M:N → 中间表单独建。**
> **方法不存库，继承三选一。**

### 在界面设计中如何应用

- 字段命名：与类图属性名一致，便于 ORM 映射
- 表单设计：1:N 关系用下拉选择外键；M:N 用多选标签
- 列表展示：M:N 中间表的关联数据通过 JOIN 展示
- CRUD 界面：直接对应表的增删改查
