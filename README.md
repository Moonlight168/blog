这是我在学习与项目实践中持续维护的一份笔记，面向和我一样在成长路上的后端开发者。

- 🆓 **完全免费**：所有内容开放访问，无任何付费门槛
- 🧠 **学习导向**：以学习路径为主线，按主题整理知识与思考

## 🎤 面试演练台（本地工具）

仓库里附带一个本地面试演练工具（`interview/`），用来自测这台站点里的知识点：AI 出题 → 你作答 → 立刻点评并给出标准答案。

- **简历驱动**：从简历目录读取 `.md` / `.txt` / `.html` 简历（HTML 自动转 Markdown），按「人员目录」分组；目录可在页面上直接改并持久化
- **逐题问答**：一条消息就是一次回答，立刻给出点评和标准答案；有疑问可直接追问——追问只答疑，不打分、不进答题历史
- **按钮切题**：「下一题」「结束」是按钮，不经模型判断，模型无权替你结束面试
- **自动归档**：回答按《面试宝典文章格式规范》写回对应知识分类，同时追加到私有答题历史；答案不合规范时先让模型按规范重写再入库
- **混合查重**：精确标题 + 关键词匹配（FTS5）+ 向量检索，RRF 融合后交模型判定是否与旧题重复
- **场次总评**：固定四段输出，其中场均分由服务端计算，不由模型生成
- **复习模式**：从题库随机抽题，只看题目 + 标准答案 + 自己历次回答，**不调用任何模型、不消耗 token**
- **检索预览**：把三路召回结果并排展示，并给出 RRF 融合排序，用来验证向量检索是否真的起作用

### 启动

```bash
cd interview
cp .env.example .env    # 填写对话模型；Embedding 可选，不配则退化为关键词检索
npm install
npm run dev
```

打开 http://127.0.0.1:5174 （后端 API 在 8890）。

> 简历与答题记录都放在 `src/private/` 下，该目录已被 `.gitignore` 排除，不会随仓库上传。工具默认只监听 `127.0.0.1`。

## 🤝 贡献指南

欢迎大家参与贡献，共同完善这份学习笔记！

### 贡献流程说明

如果你想为项目添加内容或修复问题，请按照以下步骤操作：

1. **Fork 仓库**：访问原项目的 GitHub 页面，点击右上角「Fork」按钮，将项目复制到你的 GitHub 账号下（生成你的独立远程副本）。
2. **克隆 Fork 副本到本地**：将你账号下的 Fork 仓库（远程副本）下载到本地电脑，便于开发：
   ```bash
   git clone https://github.com/你的GitHub账号/项目仓库名.git
   ```
3. **进入本地仓库目录**：
   ```bash
   cd 项目仓库名
   ```
4. **提交更改**：完成代码修改后，先将文件添加到暂存区，再提交并补充清晰的描述（说明修改目的、内容）：
   ```bash
   git add .  # 提交所有修改文件（也可指定单个文件：git add 文件名）
   git commit -m "feat: 新增用户查询接口，支持分页参数"  # 按规范填写提交信息（feat/fix/docs等前缀）
   ```
5. **推送更改到你的 Fork 仓库**：将本地修改直接推送到你 GitHub 账号下的 Fork 远程仓库（默认推送到 main 分支）：
   ```bash
   git push origin main
   ```
6. **发起 Pull Request（PR）**：
   - 访问原项目的 GitHub 页面，点击顶部「Pull requests」→「New pull request」；
   - 在对比页面，选择「base repository」为原项目仓库、「base」为目标分支（main）；
   - 选择「head repository」为你的 Fork 仓库、「compare」为你推送的分支（通常为 main）；
   - 填写 PR 标题和描述（说明修改内容、解决的问题），点击「Create pull request」完成发起。

### 注意事项

- 贡献内容必须符合项目的主题和风格
- 确保你的修改不会破坏现有功能
- 为你的修改添加清晰的描述信息
- 如果你不确定如何修改，可以先创建 Issue 进行讨论
