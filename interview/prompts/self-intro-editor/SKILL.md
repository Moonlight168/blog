# 自我介绍规范

> 面向**中文面试的口语稿**（技术面 / 人事面各一份），事实来源是本人的主简历。

## 一、两类文件的关系

| 类型 | 作用 |
|------|------|
| 通用版 | 按面试场景准备的标准稿：技术面、人事面各一份 |
| 本场版 | 某一场面试实际要说的那份：在通用版基础上按本场 JD 定制 |

- 本场版**以通用版为基础改**，不另起炉灶；只调整顺序、详略与措辞，**事实不动**
- 改了通用版之后，回头检查已投递场次的本场版是否要跟着更新

## 二、结构

```
> 链路锚点（一行，把小节串起来，如「开场 → 实习 → 项目 A → 项目 B → 收尾」）

**一、开场**
（问候 + 姓名 + 学校专业 + 应聘方向）

**二、…**
（按简历主线分 3-6 节）

**N、收尾**
（一句收束 + 致谢）
```

- **首行链路锚点是这份稿子的记忆索引**，必须保留；小节有增减时同步更新它
- 小标题用 `**一、开场**` 这种加粗写法，**不用 H1/H2**
- 小节编号连续，不跳号

## 三、篇幅与语速

- 约 **3 分钟**，≈ 550–650 字（正常语速）
- **不分「1 分钟版 / 3 分钟版」**：默认就说这一版，被要求简短时临场压缩，不另写一份

## 四、内容规则

- **事实来源是主简历**，简历没写的不写、不虚构
- 每个小节 2-4 句，讲清「做了什么 + 学到/体现了什么」，不堆技术名词
- 口语化，写出来是能直接说出口的话，不是书面总结
- 不写旁白、不解释「这段想表达什么」—— 那属于「定制思路」，不是正文

## 五、分场景侧重

| 场景 | 侧重 |
|------|------|
| 技术面 | 技术主线与项目：实习做了什么、项目里的角色与产出 |
| 人事面 | 背景与动机：专业路线、为什么选这个方向、协作方式、职业规划 |

## 六、本场定制版

在通用版基础上按本场 JD 调整：

```
## 本场版本

> 链路锚点

**一、开场** … **N、收尾**
（3 分钟口语稿）

## 定制思路

### 与 JD 的匹配点
（表格：亮点前置展开 / 弱点不主动提，被问到再说）

### 关键词布局
（业务、技术栈、能力三组关键词，按本场 JD 挑）
```

- 「定制思路」记的是**为什么这么排**，供复盘用，不念出来
- 匹配点要落到本场 JD 的具体要求上，不写泛泛的「学习能力强」

## 七、练习方式

读熟结构，记住每节的 2-3 个关键词，**不逐字背**；投递岗位变化时只微调「应聘岗位」与收尾句。

## 八、改动时的红线

- **不动结构**：链路锚点、加粗小标题写法、小节编号不要改
- **不虚构**：简历里没有的经历、数字、奖项一律不加
