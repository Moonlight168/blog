# 简历设计规范

> 面向**单页 A4、中文、技术岗**的 HTML 简历。举例里的人名、公司、项目一律是虚构的。

## 一、版式设计规范

1. **单页 A4，一屏扫完** —— 打印尺寸 A4（页边距 12-14mm），正文 12.5px、行高 1.6；信息密度控制在 HR 30 秒内读完，宁删不挤
2. **主色深蓝 + 灰阶** —— 主色 `#1a5276`（姓名、板块标题、关键词），正文 `#2c3e50`，次要信息 `#5d6d7e`；全篇仅此一色，不引入第二强调色
3. **头部三要素** —— 左：姓名（28px 加粗）+ 求职意向（岗位 + 核心方向，附 GitHub 链接）+ 联系方式一行；右：证件照（85×120，仅正式投递用）
4. **五板块固定顺序** —— 教育经历 → 专业技能 → 实习经历 → 项目经历 → 证书。**实习经历优先于项目经历**（有实习时实习永远排项目前面，HR 最先看）
5. **板块标题样式** —— 15.5px 加粗深蓝，左侧 4px 竖线 + 底部 1px 浅蓝横线
6. **条目行样式** —— 标题行左文右时间（如 `2026.06－2026.08`，浅灰 12px），信息与时间同行，不另起一行
7. **项目条目三件套** —— 每项目固定结构：`标题行（名称+角色+标签）→ 项目描述（1 句业务背景）→ 技术栈行（浅灰底纹）→ 项目职责 bullet`，职责 3-4 条，每条 ≤ 40 字
8. **关键词加粗** —— 技能、技术栈、核心动作中的关键名词用 `<strong>` 加粗，方便 HR 扫读定位；全篇加粗密度控制在 15% 以内
9. **打印优化** —— 每个实习/项目条目 `page-break-inside: avoid`，防止条目跨页截断

## 二、内容规范

1. **专业技能按栈分组** —— 按「语言与框架 / 数据与中间件 / 前端技术 / 工程工具」这类维度分组，每组一行：组名加粗 + 一句能力描述
2. **技能用「熟悉/掌握/了解」三级措辞** —— 熟练度递进，不夸大不遗漏；不写「精通」
3. **实习经历写四件事** —— 业务开发 / 接口联调 / 测试协作 / 链路验证，每条 = 加粗动作 + 具体产出（模块名、工具名、方法名）
4. **项目经历描述公式** —— `业务背景（给谁解决什么问题）+ 技术架构（用什么）+ 个人职责（做了什么）`；职责条里带技术名词，技术栈行与职责条不重复罗列
5. **一律用真实经历** —— 只写做过的，不虚构；被追问细节时能展开到代码级
6. **时间线一致** —— 教育、实习、项目时间互相衔接无矛盾；更新简历时先核对时间线
7. **证书精简** —— 只放有含金量的，一行展示，不放无关证书

## 三、排版硬性规则（HTML 简历，A4）

1. **页面** —— A4 尺寸（`@page A4`、12mm/14mm 边距），导出控制在 **2 页内**；**第一面必须出现至少一个项目**（标题即可，不能让招聘方第一面只见技能/实习）
2. **字号** —— 正文基准 13px，行数控制以此为准
3. **条目行数** —— 每条要点（技能行 / 实习 / 项目职责 li）**不得超过 2 行**；第二行若只有一两个字也算「过少」，必须压回单行；超过 2 行的必须删减
4. **估算口径** —— 13px 下 CJK≈13px、ASCII≈7px，A4 内容宽约 684px → 单行约 50-52 个汉字；超出预算即剪
5. **行数校验** —— 正文重建后用无衬线宽度估算逐条扫描，超预算条目当场删冗余字（保留数字/技术关键词，删「同时/等/独立/业务」类修饰）
6. **措辞** —— 个人优势/项目描述不加句号

## 四、改动时的红线

- **不动样式**：改文字不要顺手调整 CSS、字号、颜色、间距 —— 版式是定稿的，改了会破排版
- **不动结构**：板块顺序、条目三件套的层级不要重排
- **不虚构**：不添加简历里没有的经历、技能、证书
