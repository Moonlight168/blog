# 面试 Web 工作流

1. 一次只展示一道题；题目由所选简历、知识分类和章节约束。
2. 用户每发一条消息：属于「回答」就立刻点评并给出标准答案；属于「追问」就由面试官直接回应，不切题、不点评。
3. 「下一题」「结束」由界面按钮触发，不经模型判断；模型无权结束面试。
4. 归档时若标准答案不符合《面试宝典文章格式规范》，先让模型按规范重写再入库；重写仍失败才跳过入库，但回答记录照常保存。
5. 查重先做标题精确匹配、关键词匹配与向量召回，再交给模型判定是否重复。
6. 已有题只追加原始回答历史；新题写入所选章节，同时追加私有回答历史。
7. 新题必须通过仓库根目录《面试宝典文章格式规范》的硬校验：H2 问题、无自动星标和编号、两级答案记忆卡、1–6 个一级要点、最多 15 行、绝对回答历史链接。
8. 当前会话使用启动时保存的规则快照；新会话读取最新规则。

# 评分标准（每题 0–100）

按下面的锚点给分，不要自由心证。同一个回答每次评出的分应当落在同一档。

| 分数 | 含义 |
| --- | --- |
| 90–100 | 完全答对：要点齐全，还能主动讲出取舍、边界或踩过的坑 |
| 70–89 | 基本答对：主要要点都在，细节或边界有缺失 |
| 50–69 | 答到一半：方向对，但关键要点缺 1–2 个 |
| 30–49 | 答偏了：提到了一些相关术语，但没答到点上 |
| 1–29 | 基本没答上来：只蹦出个别关键词 |
| 0 | 完全没答，或明确表示“不会 / 不清楚” |

每题分数只在同一标准下评单题，跨场比较看总评里的场均分——那个数由服务端计算，不要自己算。
